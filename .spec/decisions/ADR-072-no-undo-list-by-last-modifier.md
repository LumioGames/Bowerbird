# ADR-072：内核不做撤销；「我这次改了什么」按最后修改者与时间查

状态：Accepted
日期：2026-11-27

## 背景

- 内核不记改动历史（ADR-024）。
- 一次真实项目接入的使用反馈（2026-11-27）提出两项需求：
  - 撤销某个执行者最近一次的批量登记；
  - 列出某个执行者这一轮登记和改过的资产，直接给出要提交到 git 的文件清单。两个 Agent 同时用一个库时，只能对着 git 的改动一个个认。
- 这两项看起来都需要内核记下每次改动。

## 决策

- ADR-024 不变：内核不记改动历史。
- **不做撤销**。原因已经由别的决定拿掉：
  - 写之前可以先试，看清会改什么再写（[ADR-068](ADR-068-writes-state-the-wanted-result.md)）；
  - 写错了，重新说一遍对的就是改回去的办法（ADR-068、[ADR-070](ADR-070-provenance-lives-in-bmeta.md)）；
  - 试运行的结果里带有每个文件「改之前」的值。调用方想留后路，自己存下这份结果，需要时把「改之前」再说一遍。内核不为此存任何东西。
- **「我这次改了什么」用查询回答**：`.bmeta` 里本来就记着最后是谁、什么时候改的。搜索增加按最后修改者筛选，与已有的按修改时间筛选合用，结果带出文件路径与它的 `.bmeta` 路径。
- 资产库放在 git 仓库里时，git 就是改动历史。

## 替代方案与否决理由

- **内核记一本改动流水，支持按批次撤销**：磁盘上多一类只增不减的数据，还要定它怎么同步、怎么清理、冲突了怎么办。ADR-024 已否决。
- **只在本机记最近几次改动用于撤销**：换一台电脑、换一个会话就没有了，使用者无法依赖。

## 兼容影响

- knowledge/features/search.md：筛选字段与文本语法增加「最后修改者」；现有的 `by` 仍然是创建者。
- knowledge/features/api-and-agent.md：查询结果带 `.bmeta` 路径。
- 代价：一个资产被两个执行者先后改过时，只查得到后一个。要分清每一处是谁改的，靠 git 或以后的历史插件。

## 实现时要定的

- 「最后修改者」在文本语法里叫什么。
- 没有 `.bmeta` 的文件（[ADR-067](ADR-067-bmeta-only-for-what-cannot-be-recomputed.md)）没有修改者，按这个条件查时不出现。
