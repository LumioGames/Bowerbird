# ADR-018：关系可以更换；文件里的引用名只当位置名，对应哪个资产以元数据文件为准

状态：Accepted
日期：2026-11-25

## 背景

演示路径 3 是「复制一张被引用的贴图，把引用改指到副本」。审查时发现两个问题：

- 模型文件（FBX、glTF）里写的是贴图的文件名，不认识 GUID。只改 Bowerbird 里的关系记录，模型打开用的还是原来那张；重新提取时关系又会被按文件名建回去。
- 「复制之后改指」这个需求本身很弱。复制多半是为了做变体，引用不该跟着动；换引用应该是人在引用方主动做的事，就像在 Unity 材质球上把贴图 A 换成贴图 B。

## 决策

- **关系只记在发起方的元数据文件里，记的是对方的 GUID**。Bowerbird 不往资产文件里写任何东西。这一点不变。
- **文件里写着的引用名只当「位置的名字」**。模型文件里的外部贴图名、`.bin` 文件名，以及打包在文件内的贴图的名字，都只表示「这里有一个位置」，不表示引用的是谁。
- **位置对应哪个资产，记在元数据文件里，以它为准**。关系增加一个可选字段 `slot`，值是文件里写的那个名字。
- **第一次自动配上**。提取阶段读到位置名后，按文件名找到资产，把带 `slot` 的引用关系写进元数据文件，不需要人处理。
- **之后不覆盖**。重新提取时，已有 `slot` 的关系保持不动；文件里新出现的位置名才自动配；文件里不再出现的位置名，对应的关系移除。
- **显示时按元数据文件找文件**。查看器加载模型时，按 `slot` 对应的关系取对方资产的内容。所以更换之后显示的是新贴图，对方改名、移动也不受影响。模型文件本身不改。
- **关系可以更换**：把一条关系的对方换成另一个资产。界面上只有关系图这一个入口，选中一条关系后更换对方。来源关系更换后，`toHash` 记为新对方当前的内容指纹。
- **复制就是复制**。副本是新资产，原来的引用仍指向原件；复制后不再提供「把引用改指到副本」。复制的其余语义不变（见 [ADR-005](ADR-005-assets-and-typed-relations.md)）。
- **批量更换只留在接口里**。「把指向 A 的关系全部换成 B」由 `POST /relations/retarget` 提供，给 Agent 用，界面上不出现。
- **导出或取用模型时带上依赖**。按 `slot` 的名字把对应的文件一起带出去，保证离开 Bowerbird 后模型仍能按文件里写的名字找到贴图。
- 完整性页里断链引用的「重新指定…」跳到关系图里对应的那条关系，不另做一套界面。

## 替代方案与否决理由

- **从文件里提取的引用只进索引、只读**（审查报告 C-08、D-10 的建议）：符合「能重算的只进索引」，但贴图改名或移动后引用会断，也不能更换。否决：应当像 Unity 的元数据文件那样，由元数据文件记引用并以它为准。
- **更换时改写模型文件里的贴图路径**：违反「永不修改原始文件」；FBX 是二进制，很难改。
- **在模型查看器里做贴图槽位**：与关系图是同一个动作的两个入口。否决：只保留「关系可以更换」这一个概念和一个入口。
- **复制后弹出「把引用改指到副本」**：把少见的用法放在了常见操作的后面。
