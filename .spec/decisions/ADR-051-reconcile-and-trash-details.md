# ADR-051：扫描对账与回收站细则——落单与缺失的划分、停放、冲突副本、库不可用、登记合并、包式资产、复制名、位置名配对、回收项

状态：提议
日期：2026-11-26

## 背景

sync-and-integrity.md 与 library-format.md 写了对账规则 R1 到 R12 和回收站，但实现时碰到不少文档没覆盖的情况。比如：
- 元数据文件读得出但文件没了，算「落单」还是「缺失」；
- 缺失资产原来的路径被别的资产占了怎么办；
- 云盘冲突副本怎么认；
- 资产库文件夹没挂上时还能不能写；
- 创建包式资产时里面的元数据文件怎么处理。

内核实现与审查时把这些逐条定了下来。本条把它们合并成文（ADR-013），待评审。

## 决策

**落单的元数据文件与文件缺失**
- 元数据文件读得出、文件不在：按 R7 当缺失资产（`missing-file`，错误）。这包括索引里从没见过的 GUID，它会成为一个新的缺失资产。
- 读得出、同一个 GUID 在别处有文件：元数据冲突，`kind: 'copy'`（多半是云盘冲突副本）。
- 读不出、旁边没有文件、索引里这个路径也没有资产、按冲突副本命名也对不上任何资产：落单的元数据文件（`orphan-sidecar`，警告，不挂在资产上）。
- 读不出、索引里这个路径有资产、文件也不在：元数据冲突加文件缺失。

**文件与元数据文件都被外部删除**
- 索引保留这条记录并标为缺失，关系不动。
- 引用它的资产不报断链，因为对方还在索引里。
- 这时元数据只剩索引里的一份：索引重建会丢掉它，之后引用它的资产报断链。
- 之后出现同内容的文件，按 R2 认回，元数据文件从索引里的一份写回。

**停放**
- 缺失资产原来的路径被另一个资产占用时，索引把它停放到 `.bowerbird/missing/<GUID>/<文件名>`，原路径记在索引的停放表里。磁盘上不建这个目录。
- 接口、界面、问题、回收信息、重新定位一律显示与使用原路径。

**云盘冲突副本**
- 先看副本里的 GUID：读得出、与正本同一个 GUID、自身没有文件的，登记 `kind: 'copy'` 的元数据冲突，带上两边的标签、修改时间与按名字推出的来源。
- 读不出的副本再按四家的命名找正本：

  | 云盘 | 命名 |
  |------|------|
  | Dropbox | ` (… conflicted copy …)`，也认 `conflict`、`冲突` |
  | Google Drive | ` (N)` |
  | iCloud | ` N` |
  | OneDrive | `-<机器名>` |

  找到正本时在正本上登记 `kind: 'broken'` 的元数据冲突，找不到时按落单的元数据文件处理。
- 两种处理：
  - 「保留本地」：副本移入回收站，回收项的 `kind` 为 `sidecar`。
  - 「保留另一份」：只限 `copy`。本地元数据文件移入回收站，副本改名到位、GUID 改成原资产的；内容指纹不同时追加一条版本。
- 资产文件本身的冲突副本不单独识别，按新文件认领。

**资产库文件夹不可用**
- `.bowerbird/library.json` 不在时（文件夹没挂上、被移走），所有写操作拒绝，返回 `not_found`「资产库文件夹现在访问不到」。
- 扫描跳过并记警告，不把整库标为缺失。
- 根文件夹本身不在时，资产库状态为 `unavailable`。

**通过路径登记已认领的文件**
- `POST /assets` 带 `path`、文件已有元数据文件时，合并而不是报冲突：
  - 标签取并集；
  - 阶段、描述、格子信息给了才替换；
  - 校验状态只在给 `exempt` 时改；
  - `origin` 只在原来为空时写；
  - 关系追加去重。
- 写之前按 ADR-046 核对磁盘上的版本。
- 带着自己的元数据文件进来、还没扫描到的文件，按原 GUID 登记。
- 元数据文件读不出，或这个 GUID 已在别的路径上：返回 `conflict`。

**包式资产的创建**
- 里面每个资产的元数据文件都移入回收站，`kind` 为 `sidecar`，同属一批。包文件夹自己的 `_folder.bmeta` 也移入，`kind` 为 `folder-meta`。
- 包的标签是里面资产人工标签的并集，再加上上级文件夹的默认标签。
- 关系：
  - 里面资产指向外面的关系，移到包上；
  - 外面指向里面的关系改指向包，`slot` 记包内的相对路径（ADR-041）。
- 入口：给了入口时记在 `fields['bowerbird.bundle'].entry`。没给时读取时依次猜：`index.html`、顶层的 HTML 文件、任一 HTML 文件、第一个文件。
- 包里不能再套包。

**缺少插件按资产登记**
- 识别阶段把「缺哪个插件」记进索引，不写元数据文件。
- 同时满足下面三条时，这个资产登记一条 `plugin-missing` 警告：
  - 没有已启用的插件认领这个资产；
  - `library.json` 的 `pluginFormats` 里，这个后缀对应一个插件；
  - 这个插件已在 `plugins` 里声明，但本机没有启用。
- 声明的插件没有任何资产级问题时，才登记一条库级的 `plugin-missing`。

**复制名与手动缩略图**
- 接口与界面的复制，一律在名字后加 `_N`：复制到别的文件夹、目标没有同名文件也加。复制 `x_1.png` 得到 `x_1_1.png`。
- 手动缩略图随副本复制。
- 扫描发现的外部复制（R9）保留磁盘上的名字，不带手动缩略图。

**版本记录**
- 恢复旧版本时追加一条版本，带 `restoredFrom: N`，说明为「恢复为 vN」。
- 扫描认领时，第一条版本的时间取文件的修改时间。接口登记、上传、创建包式资产取当前时间。

**缩略图过期（thumbnail-stale）**
- 元数据里有手动缩略图，且缩略图文件的修改时间早于最近一条版本的时间：登记一条提示级问题。
- 缩略图文件不在时不报。
- 唯一的处理是清掉手动缩略图。

**位置名配对**
- 只增删 `uses` 关系：
  - 已有的位置名关系不覆盖，即使已经断了；
  - 文件里已不再出现的 `uses` 位置名删掉。
- 只在引用方所在的文件夹及其下面找，依次试：
  1. 完整的相对路径；
  2. 更深处的同一相对路径；
  3. 只按文件名。
- 也试 URI 解码后的名字。含 `..`、以 `/` 开头、带协议的名字不配对。
- 之后才出现的文件，在每次扫描与登记之后自动补配。
- 插件标为 `embedded`（打包在文件里）的名字没配上时，不算「找不到」。

**重复身份待确认**
- 副本的元数据文件里记 `fields['bowerbird.identity']`：`{ copiedFrom, at, confirmed: false, reason, originalPath, copyPath }`。`reason` 是判定依据，取 `index`、`name`、`created`、`path` 之一。
- 据此派生 `duplicate-guid` 问题。确认或对调后删掉这个键；再复制时不带上。

**回收项**
- 一项可以是：
  - 一个资产：文件加元数据文件；
  - 单独的元数据文件：`kind: 'sidecar'`；
  - 文件夹设置：`kind: 'folder-meta'`。
- `info.json` 为 `{ bb, id, assetId, name, originalPath, deletedAt, deletedBy, bundle?, batch?, recordOnly?, kind? }`。
  - 单独的元数据文件，以及缺失资产移入回收站时，`recordOnly` 为 `true`。
- 文件夹设置不在回收站列表里显示；同一批的资产恢复到这个文件夹时，它一起恢复。
- 恢复时原位置被占：默认改名为 ` (n)`；请求带 `rename: false` 时返回 `conflict` 与建议的名字。

**不合法的位置名（ADR-048）**
- 派生一条元数据冲突，`details` 为 `{ kind: 'slot', slots: [...] }`。
- 只能「保留本地」：去掉不合法的位置名，保留关系。

**导出跳过的文件**
- 导出到目录的结果为 `{ written, dir, bytes, skipped? }`。`skipped` 列出不合法的位置名，与会落到目录外的路径，只在非空时出现。
- 导出计划与压缩包下载里直接不含这些文件。

**自动恢复不登记问题**
- R2、R6、R8 的自动恢复只写运行日志、发 `asset.updated` 事件，不登记问题。

**忽略问题**
- 忽略的问题以问题标识记在 `library.json` 的 `settings.ignoredIssues` 里，任何级别都认。
- 界面只给「内容重复」提供「忽略」。

**生产记录文件**
- `POST /records` 立即写出记录文件（Agent 先建记录、再登记产出）。
- 记录可以追加备注 `notes`；其余字段写入后不改。

**锁（工程约定）**
- 资产库的写锁按持有者令牌重入，同一操作里的嵌套调用不会自己锁住自己。
- 写锁内不等扫描：写操作需要的扫描，在释放锁之后才去等。
- 管线、查询、版本提交的钩子都在锁外运行。
- 扫描每 100 项拿一次锁，中间让出。
- 扫描收尾（完整性重算、入队）也分批让出事件循环。

## 替代方案与否决理由

- **读得出、但没有文件的元数据文件也当「落单」**：会丢掉它记着的关系与标签。当缺失资产，等文件回来还能认回。
- **缺失资产的原路径被占时直接删掉索引记录**：引用它的资产会立刻断链，文件回来也认不回。
- **只按名字识别云盘冲突副本**：各家命名会变、还有本地化的写法。读得出的副本先看 GUID 更可靠。
- **资产库文件夹不可用时照常扫描**：会把整库判成缺失，挂回来之后再认回一遍。
- **通过路径登记已认领的文件时报冲突**：Agent 很常见的做法是先把文件放进库，再补登记。报冲突只会多一步人工。
- **复制时目标没有同名就不加 `_N`**：名字不变，人在列表里分不清哪个是副本。
