# ADR-013：流程尽量不要人工步骤，自动结果给出可信度

状态：Accepted
日期：2026-11-25

## 背景

评审交互原型时，模型对照四视图需要知道四视图上每个视图画在哪里、对应模型的哪个视图。最直接的做法是让人在图上框出各个视图，并注明正、侧、背、顶。类似的人工步骤在别处也会出现：给图片标尺寸、给区域标用途、逐个确认自动匹配的结果。

Agent 参与生产后，资产产出的速度远快于人工处理的速度。任何一步要人先动手，人就成了整条流程的瓶颈；人工标注也容易漏做、做错，内容变了之后又很少有人回头维护。

## 决策

- 流程尽量不要人工步骤：能自动识别、推断的就自动完成，不设计要求人先标注才能继续的步骤。
- 自动得出的结果都给出可信度，例如匹配度、偏差的数值，让人一眼看出结果是否可靠。
- 人只在结果明显不对时介入。
- 自动结果得不出时，退回到不依赖它的方式（例如模型对照图片时只能并排），并说明原因，不转而要求人工补标。
- 人或 Agent 写一次的设计内容（设计意图、目标尺寸）是流程的输入，不算人工标注，见 [ADR-015](ADR-015-target-size-on-design-object.md)。

## 替代方案与否决理由

- **关键步骤由人标注或确认**：结果可控，但每个资产都要人处理，Agent 产出的资产要排队等人；标注本身也会漏、会错、会过时。
- **自动为主，提供人工标注作为补救**：补救入口很容易变成常规步骤，又回到人工标注；标注结果还要存放、要随内容变化失效，多出一套数据与界面。
