# ADR-060：浏览器测试中补定的外壳细则：扫描结束提示、新资产胶囊、删除确认、键盘树、图标表、创建输入要四视图、完成事件节流

状态：提议
日期：2026-11-26

## 背景

第一期的浏览器测试把 pages.md 的每一行走了一遍，发现几处文档没写到、实现要先定的做法。按 ADR-013 的规则（就近已有决定，否则少人工步骤、少丢数据）先定下，待评审。

## 决策

**扫描结束的提示条**（补充 ADR-040）
- 自己发起的扫描：「扫描完成 · 新增 {n} 个 · 发现 {m} 条问题」，有问题时带「查看」；没有变化时也回答「扫描完成，没有变化」。
- 文件监听与定时扫描只在有变化时提示；首次登记有自己的进度面板，不弹。
- 文件不见了：「扫描发现 {名称} 不见了」或「扫描发现 {n} 个文件不见了」。

**新资产胶囊**（细化评审意见 F-03）
- 正在扫描或网格是空的时候，新资产直接出现在网格里，不收进「有 N 个新资产」胶囊。
- 自己复制、恢复、作为一个资产、撤销出来的资产不算新资产。

**删除确认**
- 删除一律先不带 `force` 发出。还不知道有没有依赖方时，确认框只说「回收站保留 {days} 天，期间可以恢复。」，不说有没有依赖。
- 服务端答复「被引用」时，再弹一次「删除被引用的资产」的确认并列出依赖方，确认后才带 `force`。删除文件夹同样两步（ADR-047）。

**键盘**
- 左栏的视图、智能文件夹、文件夹是三棵可以用键盘走的树；`Shift+F10` 在树、网格单元格、列表行上打开右键菜单。
- 焦点在控件上时，空格与回车交给控件。

**图标**
- 外壳只打包图标表里的 Lucide 图标，主包因此从 2.17 MB 降到 1.26 MB。
- 插件贡献的 `icon` 传组件，或写表里有的名字；表里没有的显示兜底图标。

**创建方式的输入**
- `CreatorInput` / `CreatorInputSpec` 增加可选的 `views: true`，表示这个输入只接受四视图（元数据里有视图格子的资产）。
- `AssetSummary` 增加可选的 `hasViews`。
- 「生成模型…」这类创建方式只在选中四视图时出现，选择器也只列四视图。

**插件的两个钩子**
- `FormatView.techRows(asset, locale)`：检查器的「技术信息」由格式插件按原型的写法汇总；对比页的信息表仍按键列出，因为要算差值。
- `CompareProps.toolbar`：对比页顶栏里留给插件对比视图的位置，插件自己的选项（模型对照四视图的「对齐」）放进去，不再依赖外壳的样式名。

**完成事件**（补充 ADR-052）
- 首次就成功的处理阶段节流推送 `job.updated`：最多每 500 毫秒一条，最后一条在全部完成后，外壳的后台任务数与任务圆环据此归零。
- 插件的连续失败按工作类型分开计数（创建、动作、页面接口、访问控制、其余），只有同类成功才清零。

## 理由

- 都是让界面说清楚现在发生了什么，又不多打扰：
  - 自己发起的扫描要有回答；
  - 后台的变化只在有变化时提示；
  - 删除在不知道的时候不下结论。
- `views` 与 `hasViews` 是可选字段，旧插件与旧客户端不受影响。
