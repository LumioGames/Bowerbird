# ADR-021：界面用 shadcn/ui 做基础件、Magic UI 做动效，样式用 Tailwind

状态：Accepted
日期：2026-11-25

## 背景

[ADR-010](ADR-010-typescript-full-stack.md) 定了 React 加 Vite，但没有定用哪套界面组件。原型里的菜单、对话框、提示条都是手写的：菜单不能用方向键，对话框没有把焦点留在自己里面。设计系统是「变量加手写样式」的写法。

需求是用一套成熟、现成的界面库，不要全部自己手写。Magic UI 只有动效，没有菜单、对话框、表单、表格这些基础件；它是按 shadcn/ui 的方式分发、配着 shadcn/ui 一起用的，两者都用 Tailwind 写样式，shadcn/ui 的行为层用的是 Radix。

## 决策

- **基础件用 shadcn/ui**：按钮、菜单、对话框、弹出面板、表单、表格等，键盘操作与焦点管理由它处理。
- **动效用 Magic UI**：需要哪个效果取哪个。
- **样式用 Tailwind**，它是前两者共同的写法。
- **设计系统的变量照用**。已经定好的颜色、间距、圆角、动效时长等变量套到这套组件上，界面长相仍以原型为准。
- **设计系统里手写的组件样式不再直接使用**，只作为长相的参照。
- **外壳与插件共用这一套**。`plugin-sdk` 把这些组件与主题变量提供给插件，插件界面与外壳风格一致。这同时回答了插件系统文档里「是否允许插件引入自己的样式体系」的待解决项。
- **通用提示条**用这套库里现成的组件：从右下角弹出，几秒后渐隐消失；同时有多条时叠着排，不互相顶掉；鼠标停在上面时不消失；带「撤销」的多留几秒。报错、提示、操作结果都用它。需要人做决定的仍用居中的对话框。

## 替代方案与否决理由

- **保持变量加手写样式，只引入 Radix 处理行为**（审查报告的原建议）：不多一套写法，但每个组件的样式都要自己写，不符合「用成熟的库、少手写」。
- **只用 Magic UI**：它没有基础件。
- **不为 Magic UI 引入 Tailwind，把合用的效果照着重写**：同上，仍是手写。
