# ADR-008：缩略图由查看器代码生成，缓存放在资产库内，索引放在本机

状态：Accepted
日期：2026-11-25

## 背景

模型、视频这类资产的缩略图需要渲染才能得到。要决定由谁生成、生成结果放在哪里、什么时候更新；同时要决定索引数据库的位置。

## 决策

- 缩略图由格式插件生成。需要渲染的格式（模型、视频）复用查看器的同一套代码，在浏览器里渲染，保证缩略图与预览一致；不需要渲染的格式（图片、音频波形）在服务端生成。
- 任意一个打开着的 Bowerbird 页面充当渲染工作者，在后台完成渲染任务并回传结果。
- 缩略图与预览文件缓存在资产库内的 `.bowerbird/cache/`，位置可在本机配置中修改；删除后可以重建。
- 缓存文件以“内容指纹、被引用资产的指纹、插件版本”计算出的键命名。文件内容变化、被引用的贴图变化、插件升级，都会得到新的键并重新生成；旧文件定期清理。
- 手动指定的缩略图不属于缓存，存放在库级数据里，不被自动覆盖。
- 索引数据库放在本机数据目录，不放进资产库。
- FBX 与 OBJ 直接在浏览器里加载，不在入库时转换格式。
- 特效没有专用支持：能得到缩略图就显示，否则显示占位图，优先级低。

## 替代方案与否决理由

- **服务端用无界面的浏览器渲染**：Agent 入库的模型能立即得到缩略图，但要随包分发一个浏览器，体积与依赖都大。作为第一期之后的可选组件，运行同一套渲染代码。
- **服务端用独立的渲染实现**：不依赖浏览器，但缩略图与查看器是两套代码，效果会不一致，维护成本翻倍。
- **缓存放在本机数据目录**：不污染资产库，但每台机器都要重新生成，且缓存与库分离后不易管理。因为缓存文件按内容命名、只增不改，放在库内并被云盘同步也不会冲突。
- **索引数据库也放在资产库内**：自包含，但数据库文件位于 NAS 或云盘同步目录时容易损坏或产生冲突副本。
- **入库时把 FBX 转成 GLB**：查看器只需支持一种格式，但引入外部转换工具作为依赖。

- knowledge/features/library-format.md 定义缓存与本机数据目录的位置。
