# ADR-061：界面多语言：语言是一张表，先做中、英、日、韩，缺的按英文、中文顺序回退

状态：Accepted
日期：2026-11-26

## 背景

- 第一期的界面只有简体中文与英文两套文字。
- 外壳里的语言是写死的两个值；内置插件各自带一份中英两套的小词典。
- 插件交给外壳显示的文字（插件名、设置项标题、创建方式与动作的名字、网格角标、校验说明）只有中文，英文界面上也显示中文。
- 服务端的报错只有中文。
- 使用者定下：要做多语言，现在是中英文，以后还会有别的语言，这一期再加日语与韩语。

## 决策

**语言表**
- 支持的语言写在一处：`@bowerbird/schema` 的 `LOCALES`，目前是 `zh-CN`（简体中文）、`en`（English）、`ja`（日本語）、`ko`（한국어）。
- 设置页的语言选单、插件开发包、外壳词典都从这张表取。
- 新增一种语言的步骤：在表里加一行，补外壳的两份词典（`packages/web/src/i18n/<语言>/`），再补内置插件的文字。没补齐之前，缺的文字按下面的顺序回退，不会显示成空白或键名。

**源语言与回退**
- 简体中文是源语言：`design/docs/copy.md` 先用中文写，每份词典必须有中文的全部键。
- 查找顺序：当前语言 → 英文 → 中文。
- 测试检查：每种语言只能有中文有的键，占位符 `{name}` 与中文一致；列在「已完成」里的语言必须有全部键。

**默认语言**
- 先用使用者在设置里选过的语言（存在这台浏览器里）。
- 没选过时，按浏览器的语言列表匹配：完全一致，或语种相同（`ja-JP` → 日语，`zh-TW` → 简体中文）。
- 都不匹配时用英文。

**插件的文字**
- 插件开发包提供 `defineMessages` / `useMessages` / `translate` / `pageLocale`：插件按语言写自己的文字，必须有中文，其余可选，按同样的顺序回退。
- 插件交给外壳显示的文字（清单里的名字与设置、代码里登记的创建方式与动作、网格角标、校验说明）由插件给出各语言的译文，外壳按当前语言显示。具体做法见插件系统文档。

**服务端的报错**
- 服务端写的报错只有中文。中文界面原样显示；其他语言按错误码显示一句通用的话（`err.code.<错误码>`），没有对应句子时才显示服务端原文。

**字体**
- 日语、韩语界面把各自的系统字体放在前面（`:lang(ja)`、`:lang(ko)`），汉字按对应地区的字形显示。

**测试与截图**
- 单元测试与浏览器测试固定用简体中文跑，因为测试是照中文文案写的。
- 其他语言靠词典检查与人工截图检查。

## 不做的

- 给 Agent 的资产摘要、命令行与 MCP 的输出仍只有中文：使用它们的主要是 Agent，第一期不翻。
- 写进资产库的数据不翻译，例如版本说明「恢复为 v1」、生产记录、提交说明。它们是记录，不是界面。

## 理由

- 语言只登记在一张表里，加语言就是加数据，不改代码。
- 回退到英文比回退到中文更多人能读懂；中文作为最后一层，保证任何键都有字。

## 影响

- knowledge/features/web-shell.md「外观与多语言」、engineering.md 代码约定、plugin-system.md（插件文字）、docs/plugin-development.md。
- `ShellApi.locale` 的类型从两种语言放宽为 `Locale`。
