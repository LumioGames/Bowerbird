# ADR-012：插件安装在本机，资产库不携带可执行代码

状态：Accepted
日期：2026-11-25

## 背景

插件在服务进程内以完全信任的方式运行。资产库是一个可以被拷贝、同步、分享的文件夹。需要决定插件装在哪里：随资产库走，还是装在运行服务的机器上。

这一点是设计细化时补充的，随设计定稿一并确认。

## 决策

- 插件安装在本机数据目录，不放进资产库。
- 资产库的 `library.json` 只声明需要哪些插件及版本范围。
- 打开一个资产库时，本机缺少其声明的插件，对应格式按未知格式显示，并登记“缺少插件”问题，提示需要安装什么。
- 本机已安装但资产库未声明的插件默认不启用。
- 打开别人的资产库不会执行任何来自该资产库的代码。

## 替代方案与否决理由

- **插件随资产库存放（库内的插件目录）**：拷贝资产库即带走全部能力，体验最顺；但打开一个来历不明的资产库就等于执行其中的代码，在没有沙箱的前提下不可接受。
- **两处都支持，库内插件需要逐个确认信任**：兼顾便利与安全，但增加了一套信任确认流程。第一期不做，日后有需求再评估。

## 兼容影响

- knowledge/features/library-format.md 的 `library.json` 与本机数据目录。
- knowledge/features/plugin-system.md 的生命周期、安装更新与信任模型。
- knowledge/features/sync-and-integrity.md 的“缺少插件”问题类型。
