# ADR-011：网页与 Agent 共用一套接口；Agent 搜索默认返回全部资产并标明状态

状态：Accepted
日期：2026-11-25

## 背景

Bowerbird 同时面向人和 Agent。需要决定 Agent 通过什么方式访问，以及在资产有“待审、通过、打回”之分时，Agent 搜索默认能看到哪些资产。

后一个问题在讨论中给出了两个选项，设计定稿时按推荐方案确认。

## 决策

- 只有一套 HTTP API。网页外壳、命令行、MCP 服务都是它的客户端，外壳不使用任何 Agent 调不到的接口。
- MCP 与命令行是对 HTTP API 的薄封装，操作集保持很小：搜索、详情、追溯、登记、修改、取用、词表、体检。
- 搜索结果精简，每条都带物料阶段、校验状态与问题标记。
- 格式插件为每种格式提供给 Agent 的摘要：一段文字加一张概览图。
- Agent 搜索默认返回全部资产并标明校验状态，Agent 可以自行加条件只取已通过的资产。
- 资产库设置里提供开关，可改为“Agent 未指定校验条件时只返回已通过与免审的资产”。
- 登记或修改资产时，响应指出新出现的标签并给出相近的已有标签，抑制同义标签泛滥。

## 替代方案与否决理由

- **为 Agent 单独设计一套接口**：可以更贴合 Agent 的用法，但会出现网页能做而 Agent 不能做的操作，两套接口也会逐渐漂移。
- **Agent 搜索默认只返回已通过的资产**：更安全，但资产库起步阶段审核通过的资产很少，Agent 会经常得到空结果。保留为可切换的设置。
- **让 Agent 直接读写资产库文件夹**：不需要服务，但得不到检索、缩略图与完整性检查，写入也容易破坏元数据文件。文件夹格式公开，只读访问仍然可行。

- knowledge/features/search.md 的默认范围与 `agentSearchScope` 设置。
