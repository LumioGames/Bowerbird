# ADR-017：元数据文件后缀改为 .bmeta，目录布局沿用 Unity 式

状态：Accepted
日期：2026-11-25

## 背景

[ADR-004](ADR-004-unity-style-library-layout.md) 定下每个资产旁边放一份同名加 `.bb.json` 后缀的元数据文件。讨论原型审查结论时认为这个后缀看不懂、也不好看：`bb` 是什么意思要解释，带 `.json` 的双后缀显得啰嗦。直接叫 `.meta` 最直观，但会与 Unity 自己的元数据文件同名。

## 决策

目录布局与 ADR-004 相同，只改后缀。完整重述如下，本条取代 ADR-004：

- 资产库里是正常的目录树和原始文件名，用户看到的文件夹就是磁盘上的真实目录。
- 每个资产旁边放一份同名加 `.bmeta` 后缀的元数据文件，保存 GUID 与全部人工信息。例如 `chest.glb` 旁边是 `chest.glb.bmeta`。
- 文件内容仍是 JSON 文本，只是后缀上不写出来。
- 文件夹设置文件叫 `_folder.bmeta`；包式资产的元数据文件是「文件夹名加 `.bmeta`」，放在该文件夹旁边。
- 一个资产对应一个文件；少数必须成组的内容以整个文件夹作为一个包式资产，只能显式创建。
- 所有关系只记 GUID，不记路径。
- 不使用 `.meta` 后缀，避免与 Unity 自己的元数据文件冲突。
- 外部直接操作文件夹造成的不一致，由扫描器按明确的对账规则处理，并显式提示。

## 替代方案与否决理由

- **直接叫 `.meta`**：最直观。但从 Unity 工程里拖文件夹进资产库时，Unity 的元数据文件会被当成 Bowerbird 的；把资产库放进 Unity 工程时，Unity 会改写或覆盖这些文件。
- **`.meta.json`**：不与 Unity 冲突，编辑器也认得出是 JSON。但仍是双后缀，被认为麻烦。
- **保留 `.bb.json`**：不用改任何东西，但看不懂。
- 目录布局的其他替代方案（Eagle 式目录、每个文件夹一份汇总文件、隐藏文件）及否决理由与 ADR-004 相同。

- [ADR-004](ADR-004-unity-style-library-layout.md) 标为 Superseded。
- knowledge/features/library-format.md 目录布局、元数据文件、文件夹设置、包式资产、忽略规则里的文件名。

- 代价：系统不知道用什么程序打开 `.bmeta`，编辑器不会自动按 JSON 上色；用文本编辑器或 Agent 读取不受影响。
