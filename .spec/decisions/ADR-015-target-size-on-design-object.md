# ADR-015：目标尺寸由设计对象承载，尺寸线与各项尺寸检查都从它派生

状态：Superseded（被 [ADR-020](ADR-020-manual-review-and-builtin-checks.md) 取代）
日期：2026-11-25

## 背景

四视图的各个视图有没有画成同一个比例、模型做出来是不是设计要求的大小，都需要一个“应该多大”的基准。这个基准如果分别写在四视图和模型上，或者直接画进图里，就会重复、不一致，而且要人工维护，与 [ADR-013](ADR-013-minimize-manual-steps.md) 冲突。

## 决策

- 设计对象的说明文档（例如 `chest.md`）在 Markdown 开头的 front matter 里写一次目标尺寸：

  ```markdown
  ---
  size: 1.26 × 0.95 × 0.87 m   # 宽 × 高 × 深
  ---
  ```

- 文档插件把它提取为该设计对象的目标尺寸，进索引；人和 Agent（接口与 MCP）都从这里读取。
- 目标尺寸是写一次的设计内容，与设计意图写在同一份文档里，不是标注。
- 资产通过归属关系找到它的设计对象。由目标尺寸自动派生：
  1. 四视图上每个识别出的视图叠加尺寸线：正视图标宽和高，侧视图标深和高，顶视图标宽和深。尺寸线只叠加显示，不写进图片。
  2. 四视图一致性检查：以正视图定出比例，再用它量其余各视图，例如「侧视图高画成 1.01 m，应为 0.95 m」。
  3. 模型尺寸检查：模型包围盒与目标尺寸逐轴比较。
  4. 以上两项作为自动的校验规则：「尺寸与设计对象一致」「四视图各视图尺寸一致」。
  5. AI 插件生成四视图时，提示词从设计对象填入：正、侧、背、顶四个正交视图分开排布在纯色背景上，比例一致，写明目标尺寸。这样生成的图也便于自动识别视图区域（[ADR-014](ADR-014-auto-detect-turnaround-views.md)）。交给建模 Agent 的任务带上同一个尺寸。

## 替代方案与否决理由

- **在四视图上画尺寸线或写尺寸**：画进图里就不能随设计修改，也无法被读出来用于检查。
- **把尺寸分别写在模型、四视图的元数据文件里**：同一个尺寸要在多处重复写，容易不一致，而且属于人工标注。
- **写在设计对象元数据文件的自定义字段里**：同样是结构化的，但尺寸是设计内容，应与设计意图写在同一份文档里；人读文档、Agent 读文档正文时都能看到，离开 Bowerbird 也能读。
- **由模板插件的字段承载**：模板插件不在第一期，尺寸检查不应依赖团队是否装了模板插件。
