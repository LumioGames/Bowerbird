# 数据模型

内核的数据模型分两层：**资产**是基本单位，**带类型的关系**把资产连成生产链路。团队自己的条目规范（例如“道具需要原画、Icon、模型”）建立在这两层之上，由模板插件表达，内核不内置。

## 背景 / 目标

- 资产要有不随路径变化的身份，引用才不会断。
- 要能回答“这个模型来自哪张原画、哪段提示词”“这张原型稿切出了哪些图”。
- 要让人和 Agent 一眼分清一个物料是参考、过程产物还是游戏里实际使用的成品。
- 模型要足够通用，团队规范以后可以在不改内核的前提下叠加。

## 设计

### 资产

一个资产对应资产库里的**一个文件**。少数必须成组才有意义的内容（网页原型、Spine 动画、序列帧）以**一个文件夹**作为一个资产，称为包式资产，见 [`library-format.md`](library-format.md)。

任何文件都是资产。没有格式插件认领的文件以“未知格式”入库，显示通用图标，仍可打标签和建立关系。

扫描器看见的文件就进索引，成为资产。它要等有人给它记下信息，才有元数据文件（ADR-067）。在那之前，下表里存放在元数据文件的属性都是索引里的默认值：阶段与标签取自文件夹默认值，其余为空。

**资产的属性**

| 属性 | 字段 | 说明 | 存放 |
|------|------|------|------|
| 身份 | `id` | GUID，UUIDv7 | 元数据文件 |
| 内容指纹 | `hash` | `sha256:<十六进制>`；包式资产为目录指纹 | 元数据文件 |
| 路径 | — | 资产库内的相对路径，可变 | 由文件位置决定 |
| 物料阶段 | `stage` | `reference` / `production` / `runtime` | 元数据文件 |
| 标签 | `tags` | 人工标签，字符串数组 | 元数据文件 |
| 描述 | `description` | 人工描述 | 元数据文件 |
| 自定义字段 | `fields` | 按插件标识分命名空间的键值；`bowerbird.` 开头的命名空间留给内核 | 元数据文件 |
| AI 产出 | `auto` | AI 标签与描述，与人工信息分开 | 元数据文件 |
| 关系 | `relations` | 本资产指向其他资产的关系 | 元数据文件 |
| 校验 | `review` | 最近一次的人工校验结论 | 元数据文件 |
| 版本记录 | `versions` | 内容变化的历史记录 | 元数据文件 |
| 附属标记 | `auxiliary` | 是否为附属文件 | 元数据文件 |
| 包式标记 | `bundle` | 是否为包式资产 | 元数据文件 |
| 手动缩略图 | `thumbnail` | 手动指定的缩略图文件名 | 元数据文件 |
| 四视图格子 | `views` | 四视图图片的格子排布：几行几列、每一格是哪个视图 | 元数据文件 |
| 出处 | `provenance` | 它是怎么做出来的：方式、工具、提示词、参数、批次号等（ADR-070） | 元数据文件 |
| 创建与修改 | `created`、`modified` | 时间与执行者；`modified.by` 是最后修改者（ADR-072） | 元数据文件 |
| 技术信息 | — | 尺寸、时长、面数等，由格式插件提取 | 仅索引 |
| 分析结果 | — | 格式插件提取的结构化数据 | 仅索引 |
| 规则检查结果 | — | 校验插件的自动检查结论，只显示 | 仅索引 |

存放规则只有一条：**能从文件重新算出来的只进索引，人或 AI 给出的信息进元数据文件**（ADR-067）。AI 打的标签与描述也进元数据文件，因为重新生成要花钱，结果还可能不同。有两项容易看成可重算，其实属于真值：

- 四视图的格子信息是登记时声明的，从图片里算不出来。
- 带 `slot` 的引用关系第一次由提取阶段自动配上，之后可以更换，并以元数据文件为准。

**四视图的格子信息**

四视图是一张完整的图片资产，不拆成多个文件。图按固定格子排布，例如两行两列：左上正面、右上侧面、左下背面、右下顶面。`views` 记下分成几行几列、每一格是哪个视图，形如 `{ "rows": 2, "cols": 2, "cells": ["front", "side", "back", "top"] }`。

- `cells` 按从左到右、从上到下的顺序列出每一格，取值 `front`、`side`、`back`、`top`。
- 格子信息由生成四视图的一方（Agent 或创建插件）在登记时写入。第一期只通过接口写入。
- 程序按格子取出对应的那一块，用于查看单个视图，以及拿模型与四视图对照。
- 程序不根据长相判断一张图是不是四视图。没有 `views` 的图片与模型只能并排对照。

### 身份与内容指纹

- **GUID** 采用 UUIDv7（按时间有序）。文件第一次被看见时，索引就给它一个 GUID，它和有元数据文件的资产一样能被搜索、查看、引用（ADR-074）。
- 第一次给它记下信息时，元数据文件用的就是这个 GUID。写入元数据文件后 GUID 永不改变。
- 只被看见的文件，GUID 只在索引里。索引重建后它会换一个 GUID：磁盘上没有任何东西记着旧的。被外部工具改名或移动后，它也被当成新文件。它身上没有算不出来的信息，所以什么也不丢。
- **内容指纹**是文件内容的 SHA-256。字段带算法前缀，以后更换算法不破坏旧数据。
- 两者分工：GUID 回答“是哪个资产”，指纹回答“是哪一版内容”。替换文件内容时 GUID 不变、指纹变。
- 包式资产的指纹是其内部所有文件“相对路径加文件指纹”排序后的哈希。
- 关系只引用 GUID，不引用路径。
- 复制得到的副本是新资产，有自己的 GUID。通过界面或接口复制时，副本的文件名是原名加下划线和数字，例如 `chest.png` 的副本是 `chest_1.png`；扫描器发现的外部复制保留磁盘上的名字。复制的完整语义见 [`sync-and-integrity.md`](sync-and-integrity.md)。

### 物料阶段

`stage` 是必填字段，三个固定取值：

| 取值 | 名称 | 含义 | 例子 |
|------|------|------|------|
| `reference` | 参考素材 | 收集来的灵感与参考，不属于项目产出 | 摄影、他人作品、情绪板 |
| `production` | 生产物料 | 生产过程中的中间产物与源文件 | 原画、四视图、原型稿、高模、工程文件 |
| `runtime` | 运行时物料 | 游戏里实际使用的成品 | 导出的模型、贴图、切图、Icon、音效 |

- 新资产的阶段取自所在文件夹的默认值；没有默认值时取资产库设置的 `defaultStage`，它默认为 `production`。
- 源文件和导出的成品是两个资产，用来源关系连接，各有各的阶段。
- 阶段不是标签。标签是自由文本，无法保证每个资产都有；阶段是枚举，搜索结果里始终返回。

### 标签

- 标签是自由字符串。比较前做 Unicode 规范化（NFC）并去除首尾空白，区分大小写。
- 修改标签按「增加哪些、去掉哪些」提交，内核在当前值上应用（ADR-038）。
- 标签的定义信息（分组、颜色、别名）存在库级的 `tags.json`，与资产上的标签值分开。
- 人工标签在 `tags`，AI 标签在 `auto.tags`。界面上 AI 标签以不同样式显示，人可以采纳（移入 `tags`）或删除。
- 搜索默认同时匹配两类标签，可以限定只用人工标签。

### 校验状态

通过还是打回只由人决定。人工校验结论存在 `review` 里，绑定到被校验时的内容指纹：

| 取值 | 名称 | 含义 |
|------|------|------|
| `pending` | 待审 | 尚未校验，或内容在上次校验后变了 |
| `approved` | 通过 | 当前内容已被人工确认 |
| `rejected` | 打回 | 当前内容被人工否决，附意见 |
| `exempt` | 免审 | 不需要校验，通常由文件夹默认值给出 |

`review` 只保存最近一次的结论：状态、校验时的内容指纹、谁、什么时候、意见是什么。新的结论覆盖旧的，内核不保留校验的历史。

**有效状态的计算**：

1. `review.status` 为 `exempt` 时，有效状态是免审。
2. `review.hash` 与当前 `hash` 不一致时，有效状态是待审。
3. 其余情况取 `review.status`。

**自动检查**

- 自动检查的结果只显示，供人校验时参考，不改写 `review`。
- 内置的自动检查只有一条：模型的包围盒与设计对象的目标尺寸逐轴对照，显示数字与是否相符。
- 命名、贴图边长、面数上限这类合规检查由校验插件提供，团队按自己的规范安装或编写。插件的检查同样只显示，不阻断。
- 规则检查结果可随时重算，所以只存索引。

### 关系

关系是有向的，写在**发起方**资产的元数据文件里，表示“我依赖谁”。“谁依赖我”由索引反查。

**内置关系类型**

| 类型 | 名称 | 方向含义 | 是否记录对方版本 | 例子 |
|------|------|----------|------------------|------|
| `source` | 来源 | 本资产照着对方做出来 | 是 | 模型 → 四视图；切图 → 原型稿；Icon → 模型 |
| `reference` | 参考 | 本资产做的时候参考过对方，反向叫「被参考」 | 记下，但不跟踪 | 效果图 → 原型截图 |
| `uses` | 引用 | 本资产使用时需要对方 | 否 | 模型 → 贴图；界面 → 切图 |
| `belongs` | 归属 | 本资产属于对方代表的设计对象 | 否 | 宝箱模型 → 宝箱说明文档 |

**关系的字段**

| 字段 | 说明 |
|------|------|
| `type` | 关系类型 |
| `to` | 对方的 GUID |
| `toHash` | 建立关系时对方的内容指纹；`source`、`reference` 与插件声明要跟踪版本的关系类型使用 |
| `role` | 对方在制作中的角色，例如参考图、蒙版、四视图；仅 `source` 与 `reference` 使用，可选（ADR-070） |
| `slot` | 位置名：资产文件里写的那个引用名，例如模型文件里的贴图文件名；只能是资产库内的相对路径（ADR-048）；可选 |
| `note` | 备注，可选 |

**语义约定**

- **来源关系记住上游版本**。对方的当前指纹与 `toHash` 不一致时，本资产被标为“上游已更新，待复核”。人确认复核后，`toHash` 更新为对方的当前指纹。
- **参考关系不跟踪上游版本**（ADR-073）。它也记下建立时对方的指纹，但对方内容变了不登记「上游已更新」。截图这类随时会重截的上游用参考关系。
- **登记时说明是来源还是参考**。没说明时按来源。已有的来源关系不自动改；要改成参考，由人或 Agent 更换关系类型。
- **引用关系参与缓存失效**。被引用的资产内容变化时，引用方的缩略图和预览要重做。
- **文件里的引用名只当位置名**。模型文件里写的外部贴图名、`.bin` 文件名，以及打包在文件内的贴图的名字，都只表示“这里有一个位置”，不表示引用的是谁。位置对应哪个资产，由带 `slot` 的关系记在元数据文件里，并以它为准。提取阶段第一次读到位置名时自动配上，之后不覆盖，规则见 [`pipeline-and-cache.md`](pipeline-and-cache.md)。
- **显示时按元数据文件找文件**。查看器加载模型时，按 `slot` 对应的关系取对方资产的内容。对方改名、移动不受影响；关系更换之后，显示的是新的对方。资产文件本身不改。
- **关系可以更换**：把一条关系的对方换成另一个资产。来源关系更换后，`toHash` 记为新对方当前的内容指纹。界面上只在关系图里更换；把指向某个资产的关系全部换成另一个资产的批量更换只由接口提供，见 [`api-and-agent.md`](api-and-agent.md)。
- **归属关系的对方通常是一份说明文档**，代表设计对象本身，写设计意图和美术风格。说明文档还可以在 front matter 里写下目标尺寸，资产通过归属关系找到它：模型的包围盒与它逐轴对照，生成四视图和建模的任务也带上同一个尺寸，见 [`builtin-plugins.md`](builtin-plugins.md)。
- **同一对资产之间，同一类型的关系只有一条**。带 `slot` 的引用关系按位置名区分：同一个位置只有一条，不同的位置可以指向同一个资产。
- **不允许来源关系成环**；引用和归属不做环检查。
- **插件可以登记新的关系类型**，并声明其名称、反向名称以及是否记录对方版本。

### 出处

出处说明一个资产是怎么做出来的。它是这个资产自己的一条信息，和标签一样写在它的元数据文件里，可以改（ADR-070）。

| 字段 | 说明 |
|------|------|
| `method` | 生产方式，开放值。内置值：`ai-generate`、`manual`、`slice`、`render`、`export`、`convert`、`copy`、`other`；插件自定义的值以插件标识作前缀 |
| `tool` | 工具名称与版本，自由文本，可选 |
| `plugin` | 完成这次生产的插件，值为插件标识加版本，由内核填写；可选，库外登记的没有它 |
| `prompt` | 提示词，可选 |
| `params` | 参数，键值对，可选。约定三个常用键 `model`、`seed`、`negativePrompt`；切图的区域写在 `rect`，形如 `[x, y, w, h]`（ADR-036）；其余键自由 |
| `batch` | 批次号，形如 `bat_…`；同一次产出的资产共用一个，可选 |
| `by` | 执行者 |
| `at` | 时间 |
| `note` | 备注，可选 |

- **输入就是关系**。用了哪些资产，由来源关系与参考关系表达。关系上带 `role` 和建立时对方的内容指纹。
- **同一次产出的多个资产各写一份出处**，带相同的批次号。例如一张原型稿切出三十张小图，三十个资产各有一份出处、共用一个批次号。改其中一个不影响其余。一批产出用搜索条件 `batch` 找回。
- **批次号由谁给**：插件的一次运行由内核生成；命令行一次登记多个文件、又给了出处时自动生成一个；也可以由调用方自己给（ADR-074）。
- **出处可以改**。写错了，重新说一遍对的，内核直接改掉，改之前的内容不留（ADR-068）。改出处时没有再说批次号，保留原来的；方式没变时保留原来的插件标识。
- **插件产出**：插件没给出处时，内核写 `method` 为 `<插件标识>/<创建方式标识>`，`params` 为这次运行的参数（ADR-052）。没有任何产出的运行什么都不写，只留在任务日志里。
- **复制**得到的副本，出处的 `method` 为 `copy`，并带一条指向原件的来源关系。
- **替换文件内容后，出处原样保留**，不跟版本走。它说的是这个资产怎么来的；替换内容的人可以再说一遍（ADR-074）。
- 无论资产是库内的创建插件产出的，还是库外的工具与 Agent 生成后登记的，出处的结构相同。
- `params` 里约定的键可以用来筛选和复现。
- 提示词是全文检索的内容之一，AI 生成的资产可以用当初的提示词搜回来。

### 版本记录

资产内容每变化一次，`versions` 追加一条：

| 字段 | 说明 |
|------|------|
| `hash` | 该版本的内容指纹 |
| `size` | 字节数 |
| `at` | 时间 |
| `by` | 执行者；由扫描器发现的外部改动记为 `system:scanner` |
| `note` | 说明，可选 |
| `restoredFrom` | 恢复旧版本时追加的这一条，记下恢复的是第几版 |

- 版本记录只追加：恢复旧版本会追加一条，说明为「恢复为 vN」；恢复之后又反悔时再追加一条。
- 除了替换内容与扫描发现的改动，重新定位到内容不同的文件、处理元数据冲突时保留另一份、对调重复身份时，也会追加版本。
- 只被看见的文件不记版本历史（ADR-074）：索引里只有当前内容这一条，时间取文件的修改时间；内容变了，这一条换成新的。第一次写元数据文件时，这一条成为 v1。

内核只保存这份记录，**不保存旧版本的文件内容**。保留并读取旧内容由版本插件负责，见 [`versioning.md`](versioning.md)。标签、关系、校验结论的变化不属于版本记录，内核不记这类改动的历史；需要时由插件提供。

### 执行者

所有写操作都记下执行者，格式为 `类别:名称`：

- `user:<名称>`：人。名字在设置里填；没有提供名字时为 `user:unnamed`，界面显示为“未署名”。装了访问控制插件时，以插件识别出的名字为准（ADR-049）。
- `agent:<名称>`：Agent，名称由 Agent 提供。
- `system:scanner`：扫描器发现的外部改动。

通过创建插件产出的资产，执行者仍是发起的人或 Agent，不为插件增加新的类别；是哪个插件做的，看出处的 `plugin`。

元数据文件的 `modified` 记着最后是谁、什么时候改的信息。搜索可以按最后修改者筛选，用来回答「我这次改了什么」（ADR-072）。

执行者只用于留痕，不做任何校验，不是身份认证。

### 不变量

1. 一个资产库内，GUID 唯一。
2. 每个资产的 `stage` 必有取值。
3. 关系的 `to` 指向不存在的 GUID 时，关系保留，并登记一条断链问题。对方在回收站时也算断链；可以重新加回指向回收站里资产的关系（例如撤销「删除这条关系」），它保持断链，资产恢复后自动接上。
4. 内核与插件在读取、预览、处理资产时不修改资产文件，关系与位置的对应只记在元数据文件里；上传、登记与替换内容是使用者发起的写入。删除只是移入回收站。
5. 元数据文件里只有人工信息、AI 产出、登记时声明的信息、出处和记录（包括内核在 `fields` 的 `bowerbird.` 命名空间里记的待确认事项），不含可重算的技术信息。
6. 没有人记过信息、也没有被关系指向的文件，没有元数据文件。
7. 标签、关系、出处与校验结论只保存当前状态，内核不记它们的改动历史，也不做撤销（ADR-072）。
