# 内置插件

第一期随内核发布六个插件：五个格式插件和一个搜索插件，代码在 `plugins/` 下。它们使用与第三方插件完全相同的接口与构建方式，本身也是插件接口的参考实现。实现细则见 ADR-055（图片、视频、音频、文档、关键词搜索）与 ADR-056（3D 模型）。

## 背景 / 目标

- 覆盖游戏资产里最常见的类型，让内核开箱即可用。
- 3D 模型的查看器要达到检查制作规范的水平：PBR、通道、分屏对比、环境光照。
- 每个格式都要给 Agent 提供可用的摘要。
- 以这六个插件验证插件接口是否够用。

## 设计

### 总览

| 插件标识 | 格式 | 缩略图生成位置 | 外部依赖 |
|----------|------|----------------|----------|
| `bowerbird.image` | PNG、JPG、WebP、GIF、SVG、AVIF | 服务端（sharp） | 无外部工具 |
| `bowerbird.video` | MP4、M4V、WebM、MOV | 浏览器 | 无外部工具，自己读容器 |
| `bowerbird.audio` | WAV、MP3、OGG（Vorbis、Opus）、FLAC | 服务端 | 无外部工具，用 WASM 解码 |
| `bowerbird.model` | GLB、glTF、FBX；glTF 的 `.bin` 作为附属文件 | 浏览器 | 无 |
| `bowerbird.doc` | Markdown、HTML、TXT、JSON；带 `index.html` 的包式资产 | 不生成图片 | 无 |
| `bowerbird.search-keyword` | — | — | 无 |

- OBJ 第一期不支持，按未知格式显示。
- 六个插件都不带动作与创建方式；只有模型插件带设置项（默认环境、像素比上限）与一条自动检查。
- 六个插件的界面文字都有简体中文、English、日本語、한국어（ADR-061）；清单里交给外壳的名字与设置项在 `l10n` 里有英日韩三种译文（ADR-062）。
- 提取时写下的角标以中文为原文：模型「2,480 面」、音频「0.8 秒」；网页部分的 `formatBadge` 按界面语言说成「2,480 tris」「2,480 ポリゴン」「2,480 삼각면」等。图片的宽×高、视频的时长不带文字。
- 模型的尺寸检查由网页部分按检查结果里的数值（模型、目标、各轴）重新组句；中文与服务端写下的说明逐字相同。
- 模型在检查器里的「技术信息」与原型一样只列四行：三角面、材质、贴图（「3 张 · 最大 1024」）、动画（「1 段 · open」，片段名在提取时记进 analysis）；对比页的信息表仍逐项列出。

### 图片

**提取的技术信息**：`width`、`height`、`channels`、`hasAlpha`、`colorSpace`、`frames`（动图帧数）、`dpi`。

**缩略图**：服务端生成。
- `thumb` 为 512 像素 WebP，`preview` 为 2048 像素 WebP。
- SVG 先栅格化。
- 动图（gif、webp、avif）取第一帧，另存一份 256 像素的动态 WebP 在 `scrub` 变体里，供网格悬停播放。

**四视图的格子**：四视图是一张完整的图片资产，不拆成多个文件。各个视图按固定格子排布，例如两行两列：左上正面、右上侧面、左下背面、右下顶面。分成几行几列、每一格是哪个视图，记在元数据文件的 `views` 里：

```jsonc
"views": { "rows": 2, "cols": 2, "cells": ["front", "side", "back", "top"] }
```

- `cells` 按从左到右、从上到下的顺序，取值 `front`、`side`、`back`、`top`。
- 格子信息由生成的一方写入：Agent 或创建插件生成四视图时按格子排布，并在登记时把格子信息一起写进去。它不能从图片重新算出来，属于真值，不进可重建的索引。
- 图片插件不识别图上的物体，也不根据长相判断一张图是不是四视图。带格子信息的图片才是四视图。
- 程序按格子取图：查看某个视图、画尺寸线、拿模型与四视图对照时，按行列取出对应的那一格。
- 没有格子信息的图片只能与模型并排对比。

**查看器**

- 缩放与平移，适应窗口、原始大小、按像素放大时不做平滑。
- 背景切换：棋盘格、黑、白、自定义颜色，用于检查透明边缘。
- 通道查看：红、绿、蓝、透明度单独显示。
- 取色器：悬停显示像素坐标与颜色值。
- 主色板：提取图片的主要颜色，可复制色值。
- 平铺预览：把图片重复平铺，检查无缝贴图的接缝。
- 动图播放控制。
- 四视图可以切换看整图或正、侧、背、顶某一格。
- 尺寸线：图片带格子信息、且所归属的设计对象写了目标尺寸时，在各视图上叠加尺寸线。
  - 正视图标宽和高，侧视图标深和高，顶视图标宽和深。
  - 尺寸线按格子画，每一格是哪个视图取自格子信息。
  - 尺寸线画在格子里的图形上：图形的范围取与背景色（四个角里占多数的颜色）不同的像素的包围盒，找不到时向内缩 10%。
  - 尺寸线只叠加显示，不写进图片。
- 图片大于浏览器能显示的尺寸时，查看器显示出错状态：说明原因（「图片尺寸 {宽}×{高} 超出浏览器能显示的上限」），给「下载原文件」与「重试」。上限按浏览器单张图像能解码的大小取：任一边超过 32767 像素，或解码后的 RGBA 数据超过 5 亿字节（约 1.25 亿像素）。样例库的 world_map_16k.png（16384×9216，解码后约 604 MB）落在这一档。

**对比视图**：
- 并排、卷帘、叠加（可调透明度）、差异（标出像素不同的位置，并给出不同像素所占的百分比）。
- 尺寸不同时可选择按比例对齐或按原始像素对齐。
- 两张图宽高比相差超过 5% 时，「差异」不可用，原因是「两张图的比例不一样，差异看不出东西」。
- 切图与效果图对比时（ADR-036）：切图那次生产记录的 `params.rect` 记了它在效果图上的区域，效果图一侧就裁到这个区域，四种方式都可以用。没有区域时只能并排，原因是「这张切图没有记下它在原图上的区域，只能并排」。

**自动检查**：图片插件不带自动检查。四视图是给做模型的人或 AI 看的参考，不是验收标准。

**Agent 摘要**：尺寸、是否带透明、主色；概览图为缩略图，动图也用静止的缩略图。

### 视频

**提取的技术信息**：`duration`、`width`、`height`、`frameRate`、`codec`、`hasAudio`、`container`。服务端直接读 MP4/MOV 与 WebM 的容器，不用外部工具。

**缩略图**：浏览器渲染，有人打开页面时才渲染。
- `poster` 长边 1024 像素，`thumb` 长边 512 像素，`scrub` 是 25 帧的 5×5 拼图（每帧 160 像素）。
- 封面取时长十分之一处的一帧，不检测黑场。
- 摘要图是 6 帧的关键帧条（每帧 256 像素），存在 `turnaround` 变体里。

**查看器**

- 播放、暂停、循环、倍速、音量。
- 逐帧前进与后退，显示当前帧号与时间码。
- 设置入点与出点循环播放。
- 「把当前帧设为缩略图」「把当前帧另存为图片资产」。
  - 另存的图片复制视频的标签、阶段与归属关系，建立指向视频的来源关系，生产记录方式为 `render`；
  - 完成后提示「已另存为 {名称}，来源指向这个视频」，带「查看」。

**网格悬停**：鼠标横向移动时按位置显示 `scrub` 拼图中的对应帧，不出声，下方有一条进度线。

**对比视图**：并排与卷帘；两个视频同步播放、同步拖动，误差保持在 0.08 秒以内。

**Agent 摘要**：时长、分辨率、帧率、编码；概览图为关键帧条。

**限制**：只能处理浏览器能解码的编码。
- 浏览器无法解码的文件（例如部分 MOV）仍然入库。
- 查看器注明「当前浏览器无法解码这个视频」。
- 缩略图任务不再重试，失败原因是「这台电脑的浏览器放不了这种视频（{编码}）」。
- 转码支持留给后续插件。

### 音频

**提取的技术信息**：
- `duration`、`channels`、`sampleRate`、`bitDepth`（读得出时）、`codec`。
- `loudness`：整体响度，LUFS；静音时没有。不足 400 毫秒的音频把全部采样当一块计算（ADR-055）。
- `peak`：采样峰值，dBFS。
- `clips`：削波处数。

**缩略图**：服务端解码生成 `peaks` 波形数据（2000 段），并据此绘制 512 像素的透明 `thumb` 波形图。

**查看器**

- 波形显示，点击定位，框选区域循环播放。
- 播放、暂停、循环、音量。
- 频谱图切换。
- 显示响度与峰值，标出削波位置。

**网格悬停**：不播放。按空格打开快速预览后才播放。

**对比视图**：两条波形上下排列，共用一条时间轴；点击其中一条波形切换到播放它，播放位置保持不变。只有这一种方式，选其他方式时提示「音频按上下两条波形对齐」。

**Agent 摘要**：时长、声道、采样率、响度；概览图为波形图。

### 3D 模型

**支持的格式**：GLB、glTF、FBX。查看器的功能对这三种格式都做全。OBJ 第一期不支持，按未知格式显示。

**加载方式**：GLB 与 glTF 直接加载；FBX 用浏览器端的加载器读取，不在入库时转换。

**提取的技术信息**

| 键 | 含义 |
|----|------|
| `triangles` | 三角面数 |
| `vertices` | 顶点数 |
| `meshes` | 网格数量 |
| `materials` | 材质数量 |
| `textures` | 贴图数量 |
| `maxTextureSize` | 最大贴图边长 |
| `bones` | 骨骼数量 |
| `animations` | 动画片段数量 |
| `boundsX` / `boundsY` / `boundsZ` | 包围盒尺寸 |
| `hasUV` / `hasNormals` / `hasVertexColors` | 是否带对应数据 |
| `vertexColorSets` | 顶点色组数 |

GLB 与 glTF 的信息在服务端解析得到。FBX 在服务端只做轻量解析，包围盒等完整信息在浏览器渲染缩略图时一并回传，回传后重跑尺寸对照。

**内嵌引用**：模型文件里写着的外部贴图名、`.bin` 文件名，以及打包在文件内的贴图的名字，都只当位置名：表示「这里有一个位置」，不表示引用的是谁。位置对应哪个资产，记在模型的元数据文件里带 `slot` 的引用关系上，并以它为准。

- 第一次自动配上：提取阶段读到位置名后，按文件名找到资产，建立带 `slot` 的引用关系，不需要人处理。
- `.bin` 只在同一文件夹或上两层内有 `.gltf` 引用它时才认领，标为附属文件。
- 打包在文件里的贴图（ADR-056）：
  - glTF/GLB 里有名字的打包图片以名字为位置名，显示时有关系填了这个位置就替换；
  - FBX 只取文件名作位置名，内嵌的贴图不能替换；
  - 这些名字插件标为 `embedded`，没配上时不算「引用的文件未找到」。
- 之后不覆盖：重新提取时，已有 `slot` 的关系保持不动；文件里新出现的位置名才自动配；文件里不再出现的位置名，对应的关系移除。
- 查看器加载模型时，按 `slot` 对应的关系取对方资产的内容。关系更换之后显示的是新贴图，对方改名、移动也不受影响。模型文件本身不改。
- 导出或取用模型时，按 `slot` 的名字把对应的文件一起带出去，模型离开 Bowerbird 后仍能按文件里写的名字找到贴图。

**缩略图**：浏览器渲染，服务器不渲染。
- 有人打开页面时才由他的浏览器渲染，在那之前显示占位图；渲染结果保存在资产库里，随资产库同步。
- 默认取四分之三视角、自动取景、中性环境光；透明底，长边 512 像素，宽高比限制在 1:2 到 2:1。
- 同时渲染 `turnaround` 摘要图：正、侧、背、顶四个正交视图拼成 2×2，共用一个比例，不透明底。
- 色调映射固定为 ACES、曝光 1。

**网格悬停**：
- 鼠标停在模型上约半秒后开始加载，实时渲染转台；移开即停止。
- 模型绕自身包围盒中心的竖直轴转，相机、灯光、环境都固定。机位按缩略图的角度取一次，按转一整圈的投影来定缩放，任何角度都不出框（ADR-056）。
- 只在已经有缩略图时才转；触屏上不转。
- 不预先生成多帧缩略图；最近准备好的 3 个模型留在内存里。大文件要等几秒才动起来。

**查看器功能**

| 类别 | 功能 |
|------|------|
| 渲染 | 基于物理的材质渲染、基于图像的环境光照、色调映射可选（ACES、AgX、中性、无），曝光 −3 到 +3 EV |
| 通道 | 完整渲染、基础色、法线、粗糙度、金属度、环境光遮蔽、自发光、透明度、顶点色；可只看单个分量 |
| 检查 | 线框、线框叠加、UV 棋盘格、Matcap、面朝向（检查反面）、贴图密度 |
| 分屏 | 两路卷帘（可拖动分界线、可旋转角度）、多通道斜切分屏（2 到 4 条，默认 3 条） |
| 环境 | 内置工作室、日落、阴天、夜晚四种，在代码里生成，不带 HDRI 文件；旋转、曝光；背景显示环境、纯色或透明 |
| 灯光 | 可叠加一盏可调方向的主光，开关阴影 |
| 相机 | 轨道旋转、平移、缩放；视野角；透视与正交切换；正、背、左、右、顶、底预设视图 |
| 展示 | 转台自动旋转、地面与阴影、网格地面；包围盒尺寸与比例尺（默认显示） |
| 结构 | 网格与材质列表，可逐个显示、隐藏、单独查看；骨骼显示 |
| 动作 | 动画片段列表、播放、暂停、循环、速度、时间轴拖动 |
| 信息 | 上表中的技术信息，以及每张贴图的尺寸与用途 |
| 出图 | 截图设为缩略图；截图另存为图片资产 |

**通道查看的实现方式**：把材质的对应输入直接输出为颜色，不经过光照与色调映射。
- 基础色与自发光按 sRGB 编码，其余输出原值。
- 法线输出世界空间法线，含法线贴图。
- 分屏时每路通道单独渲染一遍、共用同一相机，材质按屏幕区域丢弃区域外的像素。
- 斜切分屏的每一条有自己的通道标签，「+」加下一个读得出的通道，多于 2 条时可以去掉：「移除这一路」是通道标签旁边一个独立的按钮，悬停或键盘焦点到达时显示，用 Tab 走得到。

**通道菜单**

- 颜色类通道（基础色、法线、自发光、顶点色）带二级菜单，可以只看一个分量；默认为「全部」，单个分量按灰度显示。法线的分量为 X、Y、Z。
- 顶点色有多组时先选组（`COLOR_0`、`COLOR_1`…），再选分量；只有一组时直接给分量；没有时显示「无」。分量只显示 R、G、B、A，不显示各分量代表什么。
- 粗糙度、金属度、环境光遮蔽标出取自哪张打包贴图的哪个分量，例如「ORM · G」。
- 读不出来的功能不置灰。某个文件里没有对应的信息时（例如一个 FBX 没有粗糙度），按钮照常显示，点击时用提示条说明「这个格式不支持」。
- 分屏时通道按钮保留位置但隐藏，工具条不跳动（E-26），各路的通道在视口上的标签里选。
- 贴图密度把每个网格的每米纹素数与整个模型的中位数比：高于 1.5 倍红、低于 0.67 倍蓝、其余绿。

**尺寸显示**

- 默认显示包围盒，并在离相机最近的三条棱上标出长度：按轴着色，单位为米。
- 同时显示比例尺。比例尺在模型中心所在的深度上准确，随缩放与视野角变化。
- 工具条的「尺寸」开关可以隐藏两者。出图时不包含它们。

**出图**：截图另存为图片资产（正方形 PNG，256、512 或 1024 像素，默认透明）。
- 自动登记一条方式为 `render` 的生产记录，记下相机、环境与通道设置、尺寸与是否透明。
- 建立指向模型的来源关系，复制模型的标签与归属关系。
- 用于从模型产出 Icon。

**对比视图**

- 并排：两个模型各占一个视口，共用一个相机；预设透视、正、侧、背、顶。
- 卷帘：两个模型渲染到同一视口，以外壳的分界线切换。
- 模型与模型只对比完整渲染。
- 下方的信息表并列技术信息，差异项高亮并给出差值，例如面数与贴图尺寸的变化。

**模型对照四视图**：一侧是模型、另一侧是带格子信息的图片（见图片的「四视图的格子」）时，支持并排、卷帘、叠加，默认为卷帘。

- 按格子信息从图上取出各个视图。模型按正、侧、背、顶分别以正交相机渲染，放到四视图上对应的那一格：底边与中心对齐，缩放到高度一致，可切换为按宽度；叠加时有「模型的不透明度」滑块，在舞台上；「对齐」（按高度 / 按宽度）放在外壳给对比视图留的顶栏位置（`toolbar`，「技术信息」之前），并排时不出现。
- 卷帘与叠加只显示当前视图那一格，格子外用这张图的底色延续，相邻的格子不露出来。
- 四视图的比例由正视图格子里图形的宽度对上目标宽度来定；图形的范围与图片查看器的尺寸线同一规则：背景色取四个角里占多数的颜色，范围是与背景色不同的像素的包围盒，找不到时向内缩 10%；测量用的栅格也与图片查看器相同（长边至多 480 像素，不放大）。
- 四视图上该视图的范围用虚线框出，模型的包围盒用实线框出，并给出两者宽高比的偏差；偏差超过 5% 时标出。
- 对照只是给人看：叠在一起显示的数字是参考，不作为检查结论，不打回。模型对照四视图不做像素差异。
- 图片没有格子信息时只能并排，并说明原因。

**模型尺寸对照**：模型所归属的设计对象写了目标尺寸时，逐轴比较模型包围盒与目标尺寸的宽、高、深，显示每个轴的数字与是否相符。相差不超过 1 厘米与目标的 2% 中较大的一个，算相符（ADR-056）。

- 结果只显示，不改变校验状态，不打回；通过还是打回只由人决定。
- 这是内置插件带的唯一一条自动检查。命名规则、贴图边长是否为 2 的幂、三角面上限都不内置，由团队按自己的规范安装或编写校验插件。

**Agent 摘要**：面数、材质数、贴图清单与尺寸、骨骼数、动画片段名；概览图为四个正交视图的拼图。概览图还没有渲染时，摘要只有文字部分。

**打不开时**：
- 需要 Draco 或 KTX2 解压的 glTF、没有 WebGL 的浏览器、取文件失败、解码失败，各有一句具体的说明。
- 只有取文件失败（再试一次可能就好）给「重试」，其余只给「下载原文件」。
- 交回服务端的渲染失败带 `retryable`：只有取文件失败为 true，其余为 false，管线不会反复重试。

**设置**：`defaultEnvironment` 查看器默认环境，四种内置环境的下拉选项（工作室、日落、阴天、夜晚），随资产库走，默认工作室，存过的其他值按工作室处理；`maxPixelRatio` 渲染时的像素比上限，只在本机，默认 2。

**限制**

- 网页渲染结果与游戏引擎内的最终效果不完全一致，查看器用于检查资产是否合乎制作规范。
- FBX 的 Phong、Lambert 材质转成标准材质显示（金属度为 0，粗糙度按高光指数换算），粗糙度、金属度通道算读不出，点击时按上面的规则提示；单位按文件里的比例换算成米。
- 独立的动画文件（只有骨骼动画、不含网格）同样按模型认领，查看器里是一个空场景。
- 用 Draco 压缩网格或必需 KTX2 贴图的文件解不了：查看器说明需要哪种解压，只给「下载原文件」（见上文「打不开时」）；可选的 KTX2 贴图退回普通图片。服务端照样读出面数等信息。

### 文档

**支持的格式与显示**

| 格式 | 显示方式 |
|------|----------|
| Markdown | 渲染为排版后的文档，支持表格、代码块、图片；可切换查看原文 |
| HTML | 在受限的沙箱框架里运行，可用于交互原型；可切换查看源码；带视口尺寸预设 |
| TXT | 原文 |
| JSON | 可折叠的树形视图与原文 |

**提取的信息**：
- `title`（首个标题或文件名）、`words`、`lines`，以及全文文本供检索（最多 512 KiB）；JSON 另有 `valid`（能否解析）。
- Markdown 的 front matter 写了 `size` 时，另外提取目标尺寸 `targetWidth`、`targetHeight`、`targetDepth`（米）。
- Markdown 里的相对图片 `![](相对路径)` 当位置名报给内核，查看器按位置名取图（ADR-055）。
- Markdown 不渲染里面的原始 HTML。

**缩略图**：不生成图片。网格单元直接渲染标题与开头几行文字：Markdown 只取正文段落，跳过标题、表格、代码块、图片行、`bb://` 引用与分隔线，一段正文都没有时退回纯文本；HTML 取页面标题与可见文字，不含 doctype 与 head 里的内容。

**Markdown 中的资产引用**：文档里可以用 `bb://<GUID>` 引用资产库里的其他资产。设计对象的说明文档用这种方式嵌入原画与参考。
- 一段里只有一个 `bb://` 链接时，渲染为带缩略图的卡片；
- 行内的链接点了跳到那个资产；
- `![](bb://…)` 直接显示那个文件。

**目标尺寸**：设计对象的说明文档在 front matter 里写一次目标尺寸：

```markdown
---
size: 1.26 × 0.95 × 0.87 m   # 宽 × 高 × 深
---
```

- 文档插件把它提取为该设计对象的目标尺寸，进索引，显示在检查器的技术信息里；人和 Agent（接口与 MCP）都从这里读取。
- 这是写一次的设计内容，与设计意图写在同一份文档里，不是标注。
- 资产通过归属关系找到它的设计对象。
- 由目标尺寸派生三项：
  - 模型尺寸对照（见 3D 模型）。
  - AI 生成四视图时写进提示词的尺寸与格子排布：正、侧、背、顶四个正交视图按格子排布，例如两行两列，比例一致，并写明目标尺寸；登记时带上格子信息。
  - 交给建模 Agent 的任务带上同一个尺寸。

**HTML 原型**

- 单个 HTML 文件直接作为资产；带有附属文件的原型作为包式资产，入口为 `index.html`。
- 运行在 `sandbox="allow-scripts"`（不带同源权限）的框架里，来源是不透明的，不能访问 Bowerbird 的接口；包里的相对路径资源经包内文件端点加载（ADR-043）。
- 视口尺寸预设：适应、手机 390×760、平板 820×620、桌面 1280×720。

**对比视图**：Markdown、TXT、JSON 按行显示文本差异，可在并排与合并两种视图间切换，并显示增加与删除的行数；HTML 并排显示两个原型，其他方式不可用，原因是「网页原型只能并排」。

**Agent 摘要**：标题与开头若干行文字；写了目标尺寸时一并给出。无概览图。

### 关键词搜索

基于 SQLite FTS5 全文检索的搜索插件，没有网页部分。检索范围、权重与中文处理见 [`search.md`](search.md) 与 ADR-053。

- 全文索引放在插件自己的数据目录里（ADR-028）；资产入索引时写入，索引重建时清空后重新送入。
- 查询时在内核给出的候选集合内检索并返回带分数的命中。
- 返回命中片段（约 64 字）与高亮位置，供界面显示匹配的上下文；命中名字时不给片段。

### 特效的处理

第一期没有特效专用插件。特效相关的文件按其载体处理：

- 录屏视频按视频处理。
- 序列帧贴图按图片处理。
- 引擎专有的特效文件按未知格式入库，显示通用图标。

能渲染出缩略图的就显示缩略图，不能的显示占位图。真实的特效预览留给后续的引擎专属插件，优先级低。
