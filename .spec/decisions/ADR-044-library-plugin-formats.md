# ADR-044：资产库记下每个声明的插件认领哪些后缀

状态：提议
日期：2026-11-25

## 背景

打开一个缺少插件的资产库时，对应格式按未知格式显示，并要提示「需要安装什么」（ADR-012）。原型里 `hero_run.skel` 显示「需要 Spine 插件（community.spine 1.4）」。但本机没有这个插件，就读不到它的清单，不知道 `.skel` 归它管；`library.json` 的 `plugins` 只有插件标识与版本范围。

本条是第一期实现时按 ADR-013 补的，待评审。

## 决策

- `library.json` 增加可选字段 `pluginFormats`：后缀 → 插件标识，例如 `{ ".skel": "community.spine" }`。
- 启用一个非内置插件时，内核把它清单里声明的后缀写进去；停用不删（以后再装上仍能对上）。
- 某个文件没有已启用的插件认领、而它的后缀在 `pluginFormats` 里对应一个已声明但本机未安装的插件时，这个资产标为「缺少插件」，并说明需要哪个插件与版本范围。
- 只增加可选字段，`bb` 版本号不变。

## 替代方案与否决理由

- **在每个资产的元数据文件里记下认领它的插件**：每个文件都要写一遍，换插件时要改成千上万个文件。
- **只在库级提示缺少插件，不落到具体资产**：原型要求网格单元与详情页显示「缺少插件」状态。

## 兼容影响

- knowledge/features/library-format.md 的 `library.json` 示例与字段说明。
- packages/schema 的 `LibraryJson.pluginFormats`。
