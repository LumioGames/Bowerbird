# 任务管线与缓存

文件第一次被看见或内容变化后，内核把它送入处理管线。管线的每个阶段由插件完成，产物写入缓存、索引或元数据文件。管线负责让资产从“一个文件”变成“可搜索、可预览、有缩略图”的状态。同一个任务队列还承载创建任务（创建插件生成新资产的一次运行）与动作任务（插件动作在选中资产上的一次运行）。

## 背景 / 目标

- 入库不能被处理拖慢：资产应当立刻可见，其余信息随后补全。
- 处理可能很慢（大模型、长视频、AI 调用），必须异步、可中断后继续。
- 模型和视频的缩略图要与查看器里看到的效果一致。
- 内容或插件变化后，过期的产物要自动重做。

## 设计

### 管线阶段

| 顺序 | 阶段 | 由谁完成 | 产物 | 产物去向 |
|------|------|----------|------|----------|
| 1 | 识别 `identify` | 格式插件 | 认领该文件的插件与格式；没有插件认领时记下缺哪个插件 | 索引 |
| 2 | 提取 `probe` | 格式插件 | 技术信息、分析结果、文件里写着的位置名、可检索文本、是否附属文件 | 索引；带 `slot` 的引用关系与附属标记写入元数据文件 |
| 3 | 派生 `derive` | 格式插件 | 网页预览用的转换文件 | 缓存 |
| 4 | 缩略图 `thumbnail` | 格式插件 | 网格用的缩略图及其变体 | 缓存 |
| 5 | 摘要 `summary` | 格式插件 | 给 Agent 的概览图与文字 | 缓存 |
| 6 | 富化 `enrich` | 富化插件 | AI 标签与描述 | 元数据文件的 `auto` |
| 7 | 校验 `validate` | 校验插件 | 规则检查结果 | 索引 |
| 8 | 入索引 `index` | 内核与搜索插件 | 可被检索 | 索引与搜索插件自己的数据库 |

**阶段说明**

- **识别**先按后缀初筛候选插件，再由插件读文件头确认。多个插件都能认领时，取清单里声明优先级最高的。无人认领的归为未知格式；包式资产与没有后缀的文件交给所有格式插件判断。
- **提取**读到的引用名只当位置名。模型文件里写的外部贴图名、`.bin` 文件名，以及打包在文件内的贴图的名字，都只表示“这里有一个位置”，不表示引用的是谁；位置对应哪个资产，以元数据文件里带 `slot` 的引用关系为准。
  - 第一次自动配上：读到位置名后，在引用方所在文件夹及其下面找资产（先按相对路径，再按文件名），把带 `slot` 的 `uses` 关系写进元数据文件，不需要人处理。
  - 之后不覆盖：重新提取时，已有 `slot` 的关系保持不动，包括对方已被更换的。
  - 文件里新出现的位置名才自动配；之后才出现的文件在每次扫描与登记后自动补配。
  - 文件里不再出现的位置名，对应的关系移除。
  - 找不到资产的外部文件记为「没找到的位置名」，在详情里返回，界面上显示为“引用的文件未找到”。插件标为打包在文件里（`embedded`）的名字没配上时不算。
  - 细则见 ADR-051。
- **四视图的格子信息**不由管线产生。它是登记时写进元数据文件的；提取阶段不根据图片的长相判断一张图是不是四视图。
- **派生**只在浏览器无法直接使用原始文件时才需要。第一期的内置格式都不需要派生。
- **摘要**的文字缓存下来，Agent 读摘要时直接用。
- **富化**插件返回的向量现在不保存；语义检索插件要用向量时，在自己的数据库里存。
- **校验**运行校验插件的自动检查。内置只有一条：模型的包围盒与所归属设计对象的目标尺寸逐轴对照，给出数字与是否相符。检查结果只显示，不改变校验状态；通过还是打回由人决定。其余合规检查由团队安装或编写的校验插件提供。
- **富化**阶段没有对应插件时直接跳过；**校验**阶段没有适用于该资产的检查时也跳过。

每个阶段相互独立：某一阶段失败不影响其他阶段，也不影响资产出现在网格里。

### 触发条件

| 事件 | 重跑的阶段 |
|------|------------|
| 文件第一次被看见 | 全部 |
| 资产内容变化 | 全部 |
| 被本资产引用的资产内容变化 | 缩略图、摘要 |
| 本资产的引用关系被更换、新增或移除 | 缩略图、摘要 |
| 本资产所归属的设计对象内容变化（例如改了目标尺寸） | 校验：设计对象的识别做完时，给所有归属它的资产排校验 |
| 浏览器交回了新的技术信息（例如 FBX 的包围盒） | 校验 |
| 负责某阶段的格式插件版本变化、插件没了 | 该阶段及其后的阶段；插件没了从识别开始（服务启动时与运行中插件变化后检查） |
| 富化、校验或搜索插件这一组有变化：升级、新增、移除，包括服务停着时发生的 | 对所有资产重做该阶段（服务启动时与运行中插件变化后检查） |
| 搜索插件的索引被清空（`clearProviders()`） | 对所有资产重做入索引 |
| 未知格式的文件现在有插件能读了 | 识别（启用插件时与服务启动时检查） |
| 人工触发重跑 | 指定阶段 |
| 人工修改标签或描述 | 仅入索引 |

**启动时找过期工作**（ADR-052）：每个资产的每个阶段做完或跳过时，在 `pipeline_stages` 里记下内容指纹、引用、插件@版本。启动时与运行中插件变化后据此找出过期的阶段，按积压优先级排队。
- 识别、提取、缩略图、摘要这些跟着格式插件走的阶段，记的是做这一步的插件@版本，与当前启用的版本不同就过期。
- 富化、校验、入索引三个阶段记的是做的时候启用着的整组富化、校验或搜索插件（各插件@版本排序后拼接），对某个资产不适用而跳过时也照样记。当前这一组与记录不同就对所有资产重做；处理过、但还没有这一阶段记录的资产也补做。所以新装的富化、校验、搜索插件会给已有资产补做。
- 插件换了内部的索引结构却没有升版本号时，内核察觉不到；插件要么升版本号，要么由内核调用 `clear()` 清空，清空之后内核会把所有资产重新喂给它。

### 任务队列

队列里有三类任务，出现在设置页的同一个任务分区里：

- **处理任务**对应“一个资产的一个阶段”。
- **创建任务**不绑定资产，对应创建插件的一次运行，由人或 Agent 发起。
  - 插件通过任务上下文报告进度、响应取消，所以创建任务有进度、可以取消；
  - 进度可以带一个后续操作（按钮文字与插件页面），请使用者到插件页面继续，例如挑选候选（ADR-042）；
  - 一次运行可以登记零个、一个或多个产出；每个产出由内核登记为资产后，照常进入处理管线；
  - 每个产出的元数据文件里各写一份出处，带这次运行的批次号（ADR-070）；插件没给出处时，内核写 `method` 为 `<插件标识>/<创建方式标识>`；
  - 没有任何产出的运行什么都不写，只留在任务日志里；
  - 没挑中的候选产出放在插件的临时目录里，不进资产库，可随时清理。
- **动作任务**（`kind: 'action'`）是插件动作在选中资产上的一次运行，经管线运行，产出的登记方式与创建任务相同。

创建方式与动作的标识写成 `<插件标识>:<标识>`。

队列的规则：

- 队列保存在本机索引数据库里，服务重启后从未完成处继续：进行中的处理任务回到排队；进行中的创建与动作任务记为失败，原因「服务重启，任务中断」。
- **优先级**：当前界面可见的资产最高，其次是最近入库的，最后是历史积压。
- **并发**：本机计算类任务的并发数为处理器核心数减一，本机配置 `concurrency` 可改。
- **扫描时让路**（ADR-065）：全库扫描真正在工作时，只运行界面可见资产的任务，一次一个；其余排队的任务等扫描结束再继续，已经在运行的照常做完。
  - 扫描只是在等重看还在写入的文件时不让路；扫描一个文件夹也不让路。
  - 创建任务、动作任务与浏览器渲染不受影响。

**任务状态**

| 状态 | 含义 |
|------|------|
| `queued` | 排队中 |
| `running` | 执行中 |
| `waiting-renderer` | 需要浏览器渲染，等有人打开页面后由他的浏览器渲染 |
| `done` | 完成 |
| `skipped` | 没有插件处理该阶段，或缓存已命中 |
| `failed` | 失败，已记录错误与能不能重试 |
| `cancelled` | 已取消 |

**失败处理**

- 处理任务（含浏览器渲染）：
  - 可重试的失败自动重试 3 次，间隔 2 秒、15 秒、60 秒；
  - 仍失败则停在 `failed`，记录错误信息，登记一条 `pipeline-failed` 问题；
  - 插件标为不可重试的失败（例如浏览器解不了这种编码）立即失败。
- 创建与动作任务不自动重试，可以手动重试，用同样的参数。
- 界面上该资产显示失败标记与原因，可以手动重试。
- 插件抛出的异常被内核拦截，不会使服务退出。

### 缩略图

缩略图由格式插件生成，有两种生成位置：

| 生成位置 | 适用 | 说明 |
|----------|------|------|
| 服务端 | 图片、音频波形 | 不需要渲染，入库后立即生成 |
| 浏览器 | 3D 模型、视频 | 用查看器的同一套代码渲染，保证缩略图与预览一致；懒加载，有人打开页面时才渲染 |

**规格**

| 产物 | 规格 | 用途 |
|------|------|------|
| `thumb` | WebP，长边 512 像素 | 网格缩略图 |
| `preview` | WebP，长边 2048 像素 | 图片的快速预览 |
| `poster` | WebP，长边 1024 像素 | 视频封面 |
| `scrub` | 视频：一张拼图，含均匀取样的 25 帧；动图：一份 256 像素的动态 WebP | 网格悬停时的拖动预览或动画 |
| `peaks` | JSON，波形峰值 | 音频波形绘制 |
| `turnaround` | 一张拼图 | Agent 摘要的概览图：模型是四个正交视图，视频是关键帧条 |

Agent 摘要的概览图依次取 `turnaround`、`thumb`，不用 `scrub`。

文档类资产不生成图片缩略图，网格里直接渲染标题与开头几行文字。

**手动缩略图**：人在查看器里截图并设为缩略图后，文件保存到 `.bowerbird/thumbs/`，元数据文件的 `thumbnail` 指向它。它不是缓存，不会被自动覆盖。资产内容在此之后变化时，登记一条 `thumbnail-stale` 问题。

### 浏览器渲染工作者

服务器不渲染。需要渲染的缩略图与摘要图懒加载，由打开页面的人的浏览器完成：

1. 需要渲染的任务入队后停在 `waiting-renderer`，资产先显示占位图。
2. 有人打开页面时，他的浏览器充当渲染工作者，向服务领取这类任务，先渲染屏幕上看得到的资产。
3. 页面调用格式插件的渲染函数，与查看器是同一套代码。
4. 渲染完把缩略图与摘要图一次交回服务，由服务保存进缓存。
5. 页面只在空闲时处理，并限制单位时间内的处理量，避免影响正在进行的操作。

**租约与核对**（ADR-052）：
- 领取时租约 120 秒，并记下当时的内容指纹、引用与插件@版本。
- 交回时任务已重排或指纹对不上，结果丢弃并重排，旧内容的缩略图不会挂到新内容上。
- 渲染失败时插件可以标明能不能重试，没标的按可重试处理。

没有人打开页面的时候不渲染。服务器上没有后台浏览器，也没有无人值守的渲染命令。

渲染结果和其他缩略图一样保存在资产库的 `.bowerbird/cache/` 里，随资产库一起同步：一个人渲染过，其他人同步下来就直接登记使用，不必重新渲染，等它的渲染任务也随之完成。

**已知限制**：Agent 批量登记模型后，在有人打开页面之前，这些模型显示占位图，缩略图与摘要图都还没有。扫描器入库的模型也是这样。

### 缓存

**位置**：在资产库内的 `.bowerbird/cache/`，随资产库一起同步与做版本管理。缓存目录可以在本机配置中按库改到别处，改了之后这台机器的缓存不再随资产库同步。缓存文件经内核的 `library` 模块写入。

**缓存键**：下面四行用换行连起来后的 SHA-256：

```text
资产内容指纹
排序后的引用，每项写成「位置名=指纹」，缺失的写「位置名=missing:<GUID>」，用逗号连起来
插件标识@插件版本
阶段:变体@阶段参数版本
```

**目录结构**：`cache/<阶段>/<键的前两位>/<键>.<扩展名>`。
- 摘要文字存为 `summary` 阶段、`text` 变体的 JSON。
- 插件通过缓存写入器写的文件放在 `cache/<阶段>/plugins/<插件标识>/<GUID>-<指纹前 8 位>/<名字>`。

**性质**

- 缓存文件一经写入不再修改。内容或插件变化会得到新的键，产生新文件。
- 因此缓存可以安全地随资产库同步：只会新增文件，不会冲突。一个人生成或渲染过的缩略图，其他人同步下来就有，不必重新生成。
- 删除整个缓存目录不丢失任何信息，只是需要重新生成；需要渲染的那部分要等有人打开页面。

**清理**（ADR-052）：每 24 小时一次，也可以手动触发。
- 已登记的缓存文件，所属资产已不存在：删除。回收站里的资产保留它的缓存。
- 没登记的文件：现存或回收站里的资产能推出这个键时直接登记使用（别的机器同步来的）；推不出时超过宽限期才删。
- 宽限期：定时清理 24 小时，手动清理 10 分钟，临时文件 1 小时。
- 只碰自己的目录结构，别的文件一概不动；「清空缓存」也只删自己的目录结构。

### 索引

索引是本机的 SQLite 数据库，内容全部可由资产库重建。主要的表：

| 表 | 内容 |
|----|------|
| `assets` | 每个资产一行：GUID、路径、格式、指纹、大小、修改时间、阶段、有效校验状态、标记位；创建时间与创建者、内容最近变化时间；缩略图宽高比、角标文本；最高问题级别；被归属的数量（用来判断是不是设计对象）；缺哪个插件；出处的方式与批次号；有没有元数据文件（`sidecar`）与最后修改者（`modified_by`）；以及元数据（有元数据文件时是它的完整副本）与元数据文件的修改时间 |
| `tags` | 资产与标签的对应，区分人工与 AI |
| `relations` | 每条关系一行，含位置名 `slot`、角色 `role`、对方当时的指纹、是否断链、是否上游已更新 |
| `tech` | 技术信息，键值形式，数值与文本分列；按「键、数值」建一个索引 |
| `analysis` | 格式插件的分析结果，按插件分开存放 |
| `probe` | 提取阶段的其他结果，例如没找到的位置名 |
| `checks` | 规则检查结果：规则、结论、消息、实测值 |
| `issues` | 完整性问题 |
| `trash` | 回收站里的项 |
| `files` | 文件的大小与修改时间，用来判断要不要重算指纹 |
| `jobs` | 任务队列，含处理、创建与动作任务 |
| `cache_files` | 已登记的缓存文件与它们的键 |
| `pipeline_stages` | 每个资产每个阶段做完时的指纹、引用与插件@版本 |
| `parked` | 停放的缺失资产与它们的原路径 |

- 全文检索不在内核的索引里：关键词搜索插件在自己的数据目录里建 SQLite 全文索引（ADR-028）。
- 文件夹上显示的数量在请求时按文件夹分组统计；固定视图的数量按需统计，数据库没变时直接用上次的结果。

**重建**：索引丢失或格式版本不匹配时，启动扫描会从头建立。重建期间服务可用，资产按扫描进度陆续出现。

### 进度通知

管线的状态变化通过事件流推送给界面：
- 处理任务在等渲染、取消、最终失败、重试之后成功时推送 `job.updated`；排队、开始运行时不推。
- 首次就成功（做完或跳过）的阶段节流推送：最多每 500 毫秒一条，带最近完成的那个任务；最后一个阶段完成后一定再推一条，外壳据此把后台任务数与左栏的任务圆环更新到 0。十万资产首次打开约每秒两条。
- 创建与动作任务在开始、每次报告进度、每登记一个产出、结束时推送。
- 缩略图就绪推送 `asset.thumbnail`。

界面据此局部刷新；有后台处理时任务概况每 5 秒拉取一次。
