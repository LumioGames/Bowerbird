# ADR-002：采用本地优先的单体架构

状态：Accepted
日期：2026-11-25

## 背景

要决定系统由哪些进程和外部服务组成。使用者以小团队为主，项目开源，要求别人拿去也能轻松跑起来。存储要求是“一个本地文件夹”，这个文件夹可以来自本地盘、NAS、云盘或 Docker 卷。

## 决策

- 一个服务进程，加内嵌的 SQLite 索引，加磁盘上格式公开的资产库文件夹。
- 资产库文件夹是唯一真值；索引是可重建的派生数据。
- Bowerbird 只把资产库当本地目录读写，不关心其背后的存储介质。
- 一条命令启动；同一套程序既能本机使用，也能部署到一台机器上供小团队共用。
- 存储读写与索引访问各自隔在内部接口之后，为日后替换留出余地，但第一期不实现其他后端。

## 替代方案与否决理由

- **服务化架构（独立数据库、对象存储、任务队列，多服务编排）**：适合大团队与海量资产，但起步重，开源使用者的上手门槛高，与“小团队为主”不符。
- **Git 原生文件库（资产与元数据全部进 Git LFS，网页为静态站点）**：有完整版本历史且不需要服务器，但网页上传、搜索、AI 检索都难以实现，对美术人员门槛高。

## 兼容影响

- knowledge/features/overview.md 的进程与部署形态。
- knowledge/features/engineering.md 的技术选型与性能基准。
- 规模超出单机能力时需要新的 ADR 引入其他存储后端。
