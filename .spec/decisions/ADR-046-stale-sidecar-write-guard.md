# ADR-046：写元数据文件前先核对磁盘上的版本

状态：提议
日期：2026-11-25

## 背景

内核的写操作以索引里保存的元数据副本为基础，算出新内容后覆盖 `.bmeta`。审查发现：别的机器同步来的改动、扫描还没收进来的外部改动，会被这次写入静默覆盖；已经登记「元数据冲突」的损坏文件也会被一次无关的写入盖掉，之后问题自动消失，人没有做过选择（违反 R10「不猜测」与「文件夹是唯一真值」）。

本条是第一期实现时（内核审查之后）按 ADR-013 补的，待评审。

## 决策

- 写 `.bmeta` 之前，比较磁盘上文件的修改时间与字节数和索引记录的 `meta_mtime_ms` 与大小。
- 一致：照常写入。
- 不一致且能解析：先按扫描的规则把磁盘版本收进索引（等同一次 R5/R4 之外的元数据更新），再在它之上应用这次操作（标签按增删、其余字段按本次给出的值）。
- 不一致且解析不了：拒绝这次写入，返回 `conflict`，保留「元数据冲突」问题，等人选择保留哪一份。
- 扫描对账在锁内重新读取要写的那一份，不用锁外的快照写回。
- 落实方式：各写操作开头先把磁盘上的版本收进索引，再在它上面应用改动；写元数据的底层函数内部再核对一次作为最后一道防线，发现磁盘版本又变了就收进来并拒绝本次写入（返回 `conflict`，调用方重做），读不出的元数据文件一律不覆盖。

## 替代方案与否决理由

- **最后写入者胜**：实现最简单，但会静默丢掉别人的修改。
- **加文件锁**：云盘与 NAS 上的文件锁不可靠。
