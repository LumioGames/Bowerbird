# ADR-023：第一期不做访问限制；登录以后由插件提供，内核留出识别身份的扩展点

状态：Accepted
日期：2026-11-25

## 背景

[ADR-009](ADR-009-no-auth-localhost-default.md) 定下内核不做登录、默认只监听本机。审查原型时指出：打开局域网访问后，网页上的安装插件、修改访问设置、用默认程序打开源文件，网络里任何人都能点，其中安装插件等于能在那台电脑上运行任何程序。审查报告建议把这几样限制为只接受本机请求。

讨论的结论是先不把事情做复杂：局域网里别人能访问是需要的，也可以接受；登录这类管理能力以后一定会有，但应该是一个插件，第一期不做。

## 决策

- **第一期不做访问限制**。打开局域网访问后，其他电脑上能用的功能与本机相同，包括安装插件。
- **风险写明**：局域网里任何人都能在那台电脑上安装插件、运行程序。打开局域网访问时的提醒保留。
- **登录以后由插件提供**：账号、密码、邮箱验证都放在插件里，内核仍然不做（与 ADR-009 一致）。
- **现在留出扩展点**。增加一类扩展点「访问控制」：插件可以在每个请求进入时识别是谁，并决定是否放行；识别出的名字作为执行者。第一期只定下这个位置，不带任何实现。
- **执行者保留最基础的记录**。不在首次打开时弹窗询问名字；没有提供名字时，执行者记为 `user:unnamed`，界面显示为「未署名」；想留名字的人在设置里填。登录插件接入后用登录的名字。
- **本机动作只在本机出现**。「用默认程序打开源文件」「在文件夹中显示」是在装 Bowerbird 的那台电脑上执行的，从别的电脑打开页面时，这两项换成「下载源文件」。这是为了好用，不是访问限制。

## 替代方案与否决理由

- **安装插件、修改访问设置只接受本机请求**（审查报告 C-11 的建议）：更安全，但增加一套「本机与远程」的区分；先不考虑。
- **加一个最简单的共享密码**：能挡住路过的人，但以后的登录插件会重做一遍。
- **在内核里做账号与登录**：与 ADR-009 冲突。
