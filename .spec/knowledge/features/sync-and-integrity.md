# 扫描对账与完整性

资产库是一个任何人都能直接操作的文件夹，所以磁盘上的实际状态随时可能与索引不一致。扫描器负责把磁盘上的变化收进来，对账规则规定每种变化怎么处理，完整性检查把所有不一致显式列出。

## 背景 / 目标

- 入库有三个入口：网页拖拽、接口推送、直接操作文件夹（包括云盘同步来的变化）。三者必须落到同一套处理逻辑。
- 改名和移动不能让引用丢失。
- 复制会带来身份和引用的歧义，规则必须明确：副本是新资产，原来的引用仍指向原件。
- 任何引用可能出问题的地方都要能被人和 Agent 查到。

## 设计

### 扫描器

**触发方式**

| 触发 | 时机 | 范围 |
|------|------|------|
| 启动扫描 | 服务启动时 | 全库 |
| 文件监听 | 运行中收到文件系统事件 | 受影响的路径 |
| 定时扫描 | 默认每 10 分钟，本机配置 `scanIntervalMinutes` 可改 | 全库；兜底监听不到的变化 |
| 手动扫描 | 界面或接口触发，可以停止，下次接着做 | 全库或指定目录 |
| 命令开头 | 服务没开、命令自己打开资产库时，先对一遍账再读写（ADR-069） | 全库 |

**工作方式**

1. 遍历目录，跳过忽略规则命中的内容。
2. 对每个文件，先比较大小和修改时间与索引中的记录。两者都没变就认为内容没变，不重新计算指纹。
3. 大小或修改时间变了，才流式计算内容指纹。
4. 把磁盘状态分成三类：有元数据文件的资产、没有元数据文件的文件、没有对应文件的元数据文件。
5. 按下面的对账规则逐条处理。

- **没变的资产**（ADR-065）：只有一个元数据文件、位置和内容指纹都与索引一致、元数据文件的修改时间和字节数也与索引记录一致的资产，对账时只在锁内再看一次修改时间与大小，不再读取元数据文件（与写入前的核对同一个标准，ADR-046）。
- **管线让路**：全库扫描进行时，管线只做界面可见资产的任务，其余等扫描结束（pipeline-and-cache.md「任务队列」）。
- **分批**：
  - 扫描每 100 项拿一次写锁，中间让出，接口请求不会被长时间挡住；
  - 扫描收尾的完整性重算与入队也分批进行，让出事件循环。
- **稳定性判断**：正在被复制或下载的文件还在变。扫描器只处理修改时间早于 2 秒的文件，更新的文件 2.2 秒后再看。
  - 修改时间在 2 秒以内、但大小和修改时间在整整 2 秒里都没变的文件，也算写完。修改时间在未来（时钟偏差、复制时带过来的日期）的文件因此也会被收进来。
  - 有文件还在等这次重看时，这次扫描不算结束：进度保持「进行中」与当前阶段，`current` 写正在等的文件，重看那一趟沿用同一个开始时间，全部看完才报完成。一个一直在变的文件会让扫描一直显示进行中，直到它停下来。
  - 停止扫描会取消等待中的重看，报「已停止」。
- **自身改动**：通过接口发起的写入会直接更新索引，并登记为预期变化。扫描器看到这些变化时不重复处理。
- **资产库文件夹不可用**：`.bowerbird/library.json` 不在时（文件夹没挂上、被移走）：
  - 扫描跳过并记警告，不把整库判为缺失；
  - 写操作一律拒绝，返回 `not_found`「资产库文件夹现在访问不到」；
  - 根文件夹本身不在时，资产库状态为 `unavailable`。

**文件监听**（ADR-052）

- 用 Node.js 自带的 `fs.watch`，开销不随文件数增长：
  - macOS 与 Windows：在根目录上用系统的递归监听，整库一个句柄。
  - 其他系统：逐个文件夹监听，`.bowerbird` 与被忽略的文件夹不监听，新出现的子文件夹自动加上。
- 逐个文件夹监听时，文件夹超过 2 万个就不监听；运行中超过上限时关掉全部监听。
- 监听不了或关掉时，靠定时扫描发现变化。资产库信息的 `watch` 说明是否在监听、方式与原因。
- 监听事件只给路径，扫描器自己判断文件是否稳定，再对这一处做一次范围扫描。

### 对账规则

| 编号 | 磁盘上的情况 | 处理 | 是否登记问题 |
|------|--------------|------|----------|
| R1 | 新文件，无元数据文件，内容与任何已知资产都不同 | 只进索引，成为只被看见的文件（ADR-067）：索引给它一个 GUID；阶段、校验、标签按文件夹默认值算，阶段没有默认值时取库设置的 `defaultStage`；创建时间取文件自己的时间；不写元数据文件 | 否 |
| R2 | 新文件，无元数据文件，内容与某个“缺失”资产相同 | 重新认领：把那份落单的元数据文件移到新文件旁（不在了就从索引里的副本写出），更新路径，GUID 与关系不变 | 否，只写运行日志、发事件 |
| R3 | 新文件，无元数据文件，内容与某个在库资产相同 | 与 R1 一样只进索引，登记“内容重复”问题，由人决定是否标为副本；两者之间已有来源关系时不登记 | 是 |
| R4 | 文件内容变了 | 更新指纹，追加版本记录，重跑处理管线，标记受影响的下游；校验结论只对审过的那一版内容有效，内容变了即回到待审，免审的仍免审 | 下游被标记 |
| R5 | 文件与元数据文件一起移动或改名 | 只更新路径 | 否 |
| R6 | 文件被移走或改名，元数据文件留在原地 | 等同 R2 | 否，只写运行日志、发事件 |
| R7 | 有元数据文件的资产，文件消失，元数据文件还在（或两者都消失），找不到相同内容的新文件 | 资产标为“缺失”，关系保留；原路径已被别的资产占用时停放（见下） | 是 |
| R8 | 元数据文件消失，文件还在，索引里有该资产 | 用索引里保存的副本恢复元数据文件，GUID 不变 | 否，只写运行日志 |
| R9 | 两份元数据文件的 GUID 相同 | 见下文“重复身份” | 是 |
| R10 | 元数据文件无法解析，或出现云盘的冲突副本 | 不猜测；资产沿用索引里最后一次有效的元数据，登记“元数据冲突”问题 | 是 |
| R11 | 关系指向的 GUID 在库里不存在 | 关系保留，登记“断链引用”问题 | 是 |
| R12 | 来源关系（以及插件声明要跟踪版本的关系类型）的 `toHash` 与对方当前指纹不一致；参考关系不在其内（ADR-073） | 登记“上游已更新”问题，直到人确认复核 | 是 |

索引里保存每份元数据文件的完整副本，R2、R8 和 R10 依赖它。

**只被看见的文件**（ADR-067、ADR-074）
- 内容变了：只更新索引里的指纹，不记版本历史，照样重跑处理管线。
- 文件消失：从索引里直接去掉，不标缺失，不登记问题。
- 被外部工具改名或移动：按一个文件消失、一个新文件出现处理，新文件拿到新的 GUID。它身上没有算不出来的信息，所以什么也不丢。
- 管线从文件算出的东西（附属文件标记、按位置名配对的引用关系）只记在索引里；有元数据文件的资产照旧写进元数据文件。
- 被别的资产的关系指向，或有人给它记下信息时，才写出元数据文件，GUID 不变。

**忽略规则变了**（ADR-067、ADR-074）
- 只被看见的文件被规则命中：从索引里消失。
- 有元数据文件的资产被规则命中：自动移出资产库。文件不动，元数据文件移入回收站，可以恢复；规则仍命中时不让恢复，提示先改 `.bbignore`。引用它的资产显示断链，与删除资产时一致。
- **移出资产库**：命令 `bb untrack`、接口 `POST /assets/{id}/untrack` 手动做同样的事。移出后文件仍在，下一次扫描把它当成只被看见的文件；不想再看见它，把它写进 `.bbignore`。

**缺失资产的细节**（ADR-051）
- 文件与元数据文件都被外部删除时，索引保留这条记录并标为缺失。这时元数据只剩索引里的一份，索引重建会丢掉它，之后引用它的资产报断链。
- 缺失资产还在索引里，引用它的资产不报断链。
- **停放**：缺失资产原来的路径已被另一个资产占用时，索引把它停放到 `.bowerbird/missing/<GUID>/<文件名>`，原路径记在索引里。磁盘上不建这个目录；接口、界面、问题、回收信息一律显示原路径。

**位置名配对**：提取阶段只增删 `uses` 关系，不覆盖已有的位置对应。
- 已经带 `slot` 的引用关系保持不动，即使已经断了；文件里新出现的位置名才自动配上；文件里不再出现的位置名对应的 `uses` 关系移除。
- 只在引用方所在文件夹及其下面找：先按完整的相对路径，再按更深处的同一相对路径，最后只按文件名。
- 之后才出现的文件，每次扫描与登记之后自动补配。
- 插件标为打包在文件里（`embedded`）的名字没配上时不算「找不到」。
- 带 `slot` 的关系断链时同样按 R11 保留，提取阶段不会按文件名另配一个资产。见 [`pipeline-and-cache.md`](pipeline-and-cache.md)。

### 重复身份

两份元数据文件带着同一个 GUID，说明有人连元数据文件一起复制了资产。处理：

1. **判定原件**（ADR-045）：
   - 路径与索引记录一致的那一份是原件。索引里记的路径不在这次扫描范围内、但那里仍是这个 GUID 时，范围内的都是副本。
   - 索引里没有记录时（例如首次打开），依次看：
     1. 去掉常见的副本后缀后与另一份同名的那一份是副本。后缀包括 ` (1)`、` copy`、` - Copy`、` 副本`、`_1` 等。
     2. 否则文件创建时间更早的是原件；拿不到创建时间时用状态改变时间。
     3. 再否则路径字典序靠前的是原件。
2. **副本换新身份**：另一份生成新 GUID，按“复制”处理。
3. **登记问题**：
   - 副本的元数据文件里记下 `fields['bowerbird.identity']`：原件、判定依据、两边的路径；
   - 据此登记「重复身份」，说明哪一份被判为原件，请人确认；
   - 判定错了可以在界面上对调；确认或对调后这个键删掉。

### 复制的语义

副本是一个新资产，原来的引用仍指向原件。无论是通过界面、接口复制，还是扫描器发现的连元数据一起的复制，结果一致：

- 副本拿到**新 GUID**。
- 副本**带走“我依赖谁”的关系**：原件的来源、参考、引用、归属关系原样复制到副本（ADR-074）。
- 副本**自动增加一条来源关系指向原件**，副本的出处方式为 `copy`（ADR-070）。
- **“谁依赖原件”的关系留在原件上**，不会跟到副本。
- 副本的版本记录从复制时刻重新开始，校验状态为待审。

**副本的名字**：
- 通过界面或接口复制时，副本的名字一律是原名加下划线和数字，复制到别的文件夹也一样（ADR-051）。`chest.png` 的副本依次是 `chest_1.png`、`chest_2.png`、`chest_3.png`；复制 `chest_1.png` 得到 `chest_1_1.png`。
- 手动缩略图随副本复制。
- 扫描器发现的复制保留磁盘上的名字，不带手动缩略图。

**复制后的提示**只是一句话，不弹对话框：

- 原件没有被引用时：“已复制为 {副本名}”。
- 原件被引用时：“已复制为 {副本名}，原来的引用仍指向原件”。

通过接口复制时，同样的信息出现在返回值里。

复制之后不提供把引用改指到副本的操作。要让某个引用方改用副本，就在关系图里更换那条关系的对方，见 [`data-model.md`](data-model.md) 的“关系可以更换”。

### 移动与改名

- 通过界面或接口：文件和元数据文件一起移动，GUID 与全部关系不变。
- 目标位置已有同名文件时，按调用方给的 `onConflict` 处理：
  - 不给：返回 `conflict`；
  - `skip`：跳过；
  - `keep-both`：自动加 `_N`；
  - `replace`：把原来的资产移入回收站再放进去。被替换的是不在资产库里的文件（被忽略的、还没扫描到的）时，返回 `conflict`；是被引用的资产时，返回 `referenced`（ADR-047）。
- 在文件夹里直接操作：只要文件和元数据文件一起动，结果相同（R5）；只动了文件，由 R6 找回。

### 替换内容

用新文件替换已有资产的内容，是产生新版本的正规途径：

1. GUID 不变，指纹更新，追加版本记录。
2. 校验状态回到待审。
3. 重跑处理管线。提取阶段不覆盖已有的位置对应，规则同 R4。
4. 所有以来源关系指向它的下游，登记“上游已更新”。
5. 所有以引用关系指向它的资产，缩略图与预览重做。
6. 安装了版本插件时，由插件保存旧内容；否则旧内容不保留。

上传时遇到同名文件，界面给出三个选择：替换为新版本、保留两者（新文件自动改名）、跳过。

### 写元数据文件前的核对

写 `.bmeta` 之前，先比较磁盘上文件的修改时间与字节数和索引里的记录（ADR-046）：
- 一致：照常写入。
- 不一致、能解析：先把磁盘版本收进索引，再在它之上应用这次操作；标签按增删应用（ADR-038）。
- 解析不了：拒绝写入，返回 `conflict`，保留「元数据冲突」问题，等人选择。

扫描对账在锁内重新读取要写的那一份。

### 删除与回收站

- 删除是把资产文件和元数据文件一起移入 `.bowerbird/trash/<回收标识>/`，并在 `info.json` 里记下原路径、时间、执行者。只被看见的文件移入回收站时记 `seen: true`，恢复时只回来文件，不生出元数据文件（ADR-074）。
- **删除前确认**：
  - 界面上删除任何资产都先弹确认；
  - 资产被其他资产引用时，确认框里多一句提示，并列出引用方；
  - 接口删除被引用的资产需要显式带上强制参数，否则返回“被引用”错误和引用方列表。
- 删除后，指向它的关系成为断链问题，不会被自动清除。
- 缺失资产移入回收站时只有记录（`recordOnly`）。
- **删除文件夹**（ADR-047）：
  - 里面有资产被文件夹外的资产引用时，不带 `force` 返回 `referenced` 并列出引用方。
  - 只把资产与没被忽略的 `_folder.bmeta` 移入回收站，同属一批。被忽略的文件原样留下，文件夹因此不空时保留文件夹，空了的文件夹删除。
  - 拒绝删除库根、`.bowerbird` 及其内部、被忽略的文件夹；包式资产要按资产删除。
- **回收项的种类**：
  - 资产；
  - 单独的元数据文件（`kind: 'sidecar'`，例如处理冲突时被替下的那一份、移出资产库的资产的那一份）；
  - 文件夹设置（`kind: 'folder-meta'`）。文件夹设置不在回收站列表里显示，同一批的资产恢复到这个文件夹时一起恢复。
- **恢复**：
  - 回到原路径，GUID 不变，断链自动消失；
  - 原路径被占用时自动改名为 ` (n)` 并提示，接口带 `rename: false` 时改为返回 `conflict` 与建议的名字。
- **保留**：回收站里的内容默认保留 7 天，到期后自动清除；提前彻底删除需要人确认。保留天数是资产库的设置，即 `library.json` 的 `settings.trashDays`。
- **不永久删除别的东西**：移动、上传时的替换与重新定位，被替换掉的一律进回收站；不在资产库里的文件不覆盖。

### 完整性问题

所有不一致汇总为“问题”，在界面的完整性页和接口里可查。级别在界面上叫「错误」「警告」「提示」（ADR-035）。

| 类型 | 级别 | 含义 | 可执行的处理 |
|------|------|------|--------------|
| `broken-reference` | 错误 | 关系指向不存在的资产 | 重新指定、删除该关系、从回收站恢复对方 |
| `missing-file` | 错误 | 资产的文件不见了 | 重新定位文件、确认删除 |
| `duplicate-guid` | 错误 | 出现重复身份，已自动处理，待确认 | 确认、对调原件与副本 |
| `metadata-conflict` | 错误 | 元数据文件损坏（`broken`）、有云盘冲突副本（`copy`）、或位置名不合法（`slot`） | 选择保留哪一份；`slot` 只能保留本地并去掉不合法的位置名 |
| `stale-upstream` | 警告 | 上游内容在建立来源关系之后变了；参考关系不登记 | 确认已复核、替换本资产内容 |
| `orphan-sidecar` | 警告 | 读不出、旁边没有文件、也对不上任何资产的元数据文件 | 重新定位文件、移入回收站 |
| `pipeline-failed` | 警告 | 处理管线的某一步失败；同一资产的几步因同一个原因失败时只登记一条，先失败的那步好了以后，后面那步若还失败再登记 | 重试、查看错误 |
| `plugin-missing` | 警告 | 这个资产的格式归一个库里声明了、本机没装的插件（ADR-044）；没有资产级问题时登记一条库级的 | 安装插件 |
| `thumbnail-stale` | 提示 | 手动指定的缩略图早于当前内容 | 清除手动缩略图 |
| `duplicate-content` | 提示 | 两个资产内容完全相同 | 标为副本（ADR-037）、忽略 |

**元数据文件读得出、但没有文件**时，按 R7 当缺失资产，不算落单（ADR-051）。

**约定**

- 问题不会自动消失，除非其成因消失（例如断链的对方被恢复）。
- 每条问题都能定位到具体资产和具体关系；落单的元数据文件与库级的缺少插件只能定位到路径或插件。
- 断链引用的“重新指定”就是在关系图里更换这条关系的对方：从完整性页跳到关系图里对应的那条关系，在那里更换，不另做一套界面。
- 搜索结果里，带错误级或警告级问题的资产带有标记。
- “忽略”一条问题会被记住：问题标识记在 `library.json` 的 `settings.ignoredIssues`，同样的成因不再提示。界面只给「内容重复」提供忽略。

### 多机同步时的行为

多台机器各自运行 Bowerbird 并通过云盘同步同一个文件夹时：

- 每个资产最多一份元数据文件，冲突范围限于单个资产。
- 写元数据文件前核对磁盘上的版本，别的机器同步来的改动不会被静默覆盖（ADR-046）。
- 两台机器同时改了同一个资产的元数据，云盘会生成冲突副本，由 R10 交给人处理（ADR-051）：
  - 读得出的副本按里面的 GUID 找到正本；
  - 读不出的按 Dropbox、Google Drive、iCloud、OneDrive 的命名找正本，命名见 [`library-format.md`](library-format.md)；
  - 「保留另一份」时，副本改名到位、GUID 改成原资产的。
  - 资产文件本身的冲突副本按新文件处理（R1 或 R3）。
- 缩略图保存在资产库的 `.bowerbird/cache/` 里，随资产库一起同步：一个人渲染过，其他人同步下来就直接登记使用（ADR-052）。
- 只看的人用浏览器访问已有的 Bowerbird 服务，不需要同步。要在本机改文件的人，把整个资产库文件夹同步到本机，并在本机启动 Bowerbird。
- 同步用什么工具不由 Bowerbird 管。
