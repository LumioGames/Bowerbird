# ADR-043：HTML 资产在不带同源权限的沙箱框架里运行

状态：提议
日期：2026-11-25

## 背景

api-and-agent.md 要求网页原型类资产「在受限的沙箱框架里渲染，使用独立来源，无法访问 Bowerbird 的接口」。一个进程只有一个端口，开第二个来源要多占端口。

本条是第一期实现时按「先找最接近的已有决定，找不到就选更少人工步骤、更不容易丢数据的做法」（ADR-013）补的，待评审。

## 决策

- HTML 资产放在 `sandbox="allow-scripts"` 的框架里运行，不给 `allow-same-origin`：框架的来源是不透明的，读不到外壳页面，也带不上外壳的来源。
- 服务拒绝来源为 `null` 或不在允许列表里的接口请求，所以框架里的脚本调不到 Bowerbird 的接口。
- 包式资产里的相对路径资源通过包内文件端点加载。
- 例外：沙箱里的页面加载自己的模块脚本、样式、图片时，请求的来源同样是 `null`。只有同时满足「子资源请求（`Sec-Fetch-Dest` 为 script、style、image、font 等）」与「`Referer` 来自本服务同一资产的包内文件地址」时，包内文件端点才放行并回 `Access-Control-Allow-Origin: null`；没有 `Referer` 或来自别处一律拒绝，免得任意网站的沙箱框架跨站读取包内文件。

## 替代方案与否决理由

- **单独开一个端口作为第二个来源**：要多占一个端口，局域网部署时还要多开一个。

## 兼容影响

- knowledge/features/api-and-agent.md 安全一节；builtin-plugins.md HTML 原型。
