# ADR-066：文件改动的通知目标改为 3 秒内，保留 2 秒的稳定性等待

状态：Accepted
日期：2026-11-26

## 背景

- engineering.md「性能基准」写的目标是「单个文件变化到事件发出：2 秒内」。
- 扫描器只处理 2 秒内没再变化的文件（sync-and-integrity.md「稳定性判断」），免得处理到复制或下载到一半的文件。光这一等就占满了 2 秒。
- 十万资产的基准里实测 2.7 秒：2 秒等待，加上发现改动、算指纹、对账、发事件。两条规定不能同时满足。
- 使用者定下：保留等待。

## 决策

- 保留 2 秒的稳定性等待，规则不变。
- 目标改为：单个文件变化到事件发出 3 秒内（含 2 秒的稳定性等待），即等待结束后 1 秒内发出。
- 性能基准程序按新目标对照。

## 替代方案与否决理由

- **缩短或取消等待，保住 2 秒目标**：复制大文件、云盘同步写到一半时会被当成写完处理，算出错误的指纹、生成坏缩略图，之后还要再处理一遍。

## 影响

- knowledge/features/engineering.md「性能基准」。
- tests/perf/run-perf.mjs 的目标对照表。
