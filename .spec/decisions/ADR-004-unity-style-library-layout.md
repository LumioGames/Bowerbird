# ADR-004：资产库采用 Unity 式目录与同名元数据文件

状态：Superseded（被 [ADR-017](ADR-017-bmeta-sidecar-suffix.md) 取代）
日期：2026-11-25

## 背景

要决定资产在磁盘上如何组织，以及资产的身份与元数据存在哪里。要求是：改名和移动不丢引用；人和 Agent 直接打开文件夹能看懂；多机同步时冲突范围小。

## 决策

- 资产库里是正常的目录树和原始文件名，用户看到的文件夹就是磁盘上的真实目录。
- 每个资产旁边放一份同名加 `.bb.json` 后缀的元数据文件，保存 GUID 与全部人工信息。
- 一个资产对应一个文件；少数必须成组的内容以整个文件夹作为一个包式资产，只能显式创建。
- 所有关系只记 GUID，不记路径。
- 不使用 `.meta` 后缀，避免与 Unity 自己的元数据文件冲突。
- 外部直接操作文件夹造成的不一致，由扫描器按明确的对账规则处理，并显式提示。

## 替代方案与否决理由

- **Eagle 式目录（每个资产一个以 GUID 命名的目录，文件夹结构只存在于元数据里）**：不怕外部乱动，但直接打开文件夹看不懂，必须经过 Bowerbird 才能使用，与“文件夹即真值、离开工具仍可用”相悖。
- **每个文件夹一份汇总的元数据文件**：文件数量少，但移动单个文件会丢失其条目，多机同时编辑同一文件夹时冲突范围大。
- **元数据文件设为隐藏文件**：减少视觉干扰，但用户在文件管理器里移动资产时会把它落下。

## 兼容影响

- knowledge/features/library-format.md 定义目录布局与元数据文件结构。
- knowledge/features/sync-and-integrity.md 定义对账规则，包括文件与元数据文件分离、重复身份等情况。
- 代价：有人只移动文件而没带上元数据文件时，需要靠内容指纹重新认领。
