# 原型修订提示词

把下面整段交给负责修订原型的 Agent（或人）。它的依据是 2026-11-25 审查并逐条讨论之后定下的决策（ADR-016 至 ADR-026）。在仓库根目录运行。

```text
你要按最新的决策修订并补齐 Bowerbird 的高保真交互原型。Bowerbird 是一个开源、网页版的游戏资产管理器。原型在 design/prototype/，它已经评审过一轮；之后做了一次对照审查并逐条讨论，定下了十一条新的决策，其中三条取代了旧决策。你的任务有三件：把原型里与新决策不符的地方改掉；把文档里有、原型没画的界面补上；自己再走一遍，查漏补缺。

【先读这些，按顺序】
1. design/README.md：原型怎么打开、文件怎么分。
2. .spec/AGENTS.md、.spec/knowledge/README.md：项目是什么、知识导航。
3. .spec/decisions/README.md，以及 ADR-016 至 ADR-026 全文。ADR-004、ADR-014、ADR-015 已被取代，不再作为依据。
4. design/review/2026-11-25-review.md：先读第 5 节「讨论后的结论」，再读 E 节（没做好的）和 F 节（框架有、原型没设计的）。第 5 节与前面各节不一致时，以第 5 节为准。
5. .spec/knowledge/features/ 下的 web-shell.md、builtin-plugins.md、plugin-system.md、search.md、sync-and-integrity.md、api-and-agent.md。
6. design/docs/ 下的 pages.md、components.md、copy.md、deviations.md。
7. design/prototype/ 的源码。

【冲突时听谁的】
ADR-016 至 ADR-026 与审查报告第 5 节 > 功能文档 > 审查报告其余各节 > 原型现状。
决策没有覆盖到、你又拿不准的，不要自己定，写进交付物的「待确认」。

【约束】
- 原型继续用现在的写法（HTML、CSS、原生脚本、three.js），不改成 React 或 Tailwind。ADR-021 约束的是程序实现；但提示条、对话框、菜单的位置与行为要按它描述的样子做。
- 高保真，可以直接打开查看。界面上的文字只留关键信息，不放解释性的注释和说明段落。
- 沿用现有的设计系统变量与视觉语言，不另起一套。
- 不增加决策与文档里没有的新功能。
- 左下角「图层」评审控制保留，它不是产品界面。需要演示新状态时往里加开关。
- 样例数据只是示意，可以为演示新的规则而修改。
- 只改 design/prototype/ 与 design/docs/，不改 .spec/。

【一、要改的：与新决策不符的地方】

1. 元数据文件后缀（ADR-017）
   界面上所有出现 .bb.json 的地方改成 .bmeta。完整性页里云盘冲突副本的文件名、落单的元数据文件等样例文字一并改。

2. 复制与关系（ADR-018）
   - 复制之后不再弹对话框，也没有「把引用改指到副本…」。只出一条提示条：没被引用时「已复制为 {副本名}」；被引用时「已复制为 {副本名}，原来的引用仍指向原件」。都带「撤销」。
   - 副本的名字是原名加下划线和数字：chest_basecolor_1.png、_2、_3。
   - 关系可以更换，入口只有关系图：选中一条关系，更换它的对方，从资产里选另一个，确认后生效，可以撤销。
   - 由文件里的引用名自动配上的关系，在关系上显示位置名，例如「基础色 · chest_basecolor.png」。
   - 更换之后，模型查看器显示的是更换后的贴图。
   - 完整性页里断链引用的「重新指定…」跳到关系图里对应的那条关系。
   - 演示路径 3 改为：复制 chest_basecolor.png，看到提示条；打开 chest.glb 的关系图，把「基础色」这条关系换成副本；在关系图里确认。

3. 四视图（ADR-019）
   - 去掉视图区域的自动识别与匹配度，包括界面上那个百分数。
   - 样例 chest_turnaround.png 改成两行两列的格子排布（左上正面、右上侧面、左下背面、右下顶面），并带格子信息。检查器里显示这张图的格子信息，只读。
   - 图片查看器可以在整图与各个视图之间切换。
   - 模型对照四视图按格子取对应的视图，并排、卷帘、叠加都做，默认卷帘。
   - 没有格子信息的图片只能与模型并排；点卷帘或叠加时用提示条说明。
   - 贴图、切图合集不再被当成四视图。

4. 校验（ADR-020）
   - 校验页签的自动检查只留一条：模型的长宽高与设计对象的目标尺寸对照，显示数字与是否相符。它只显示，不改变校验状态。
   - 去掉三角面上限、贴图边长为 2 的幂、命名规则、四视图各视图尺寸一致这四条。
   - 没有自动检查项的资产，校验页签给出相应的空状态。
   - 通过还是打回只由人决定，校验队列里不再有「自动打回」。
   - 没有讨论、保持原样的两处：四视图上的尺寸线改为按格子画；模型对照四视图时宽高比偏差超过 5% 的标示保留。

5. 提示条（ADR-021）
   所有提示条从右下角弹出，几秒后渐隐消失；同时有多条时叠着排，不互相顶掉；鼠标停在上面时不消失；带「撤销」的多留几秒。需要人做决定的仍用居中的对话框。

6. 3D（ADR-022）
   - 支持的格式是 GLB、glTF、FBX。OBJ 按未知格式显示。
   - 某个文件读不出某项信息时，按钮照常显示，点击时用提示条说明「这个格式不支持」。在样例里选一个 FBX 演示这种情况。
   - 顶点色只显示 R、G、B、A，去掉各组、各分量含义的文字。
   - 网格里鼠标停在模型上约半秒后开始实时转台，移开即停。

7. 访问与名字（ADR-023）
   - 不在首次打开时询问名字。设置里有一个填名字的地方；没填时，执行者在各处显示为「未署名」。
   - 插件的安装保持可用。「安装插件…」改成填 npm 包名或本机路径，去掉 .bbplugin 的说法。
   - 评审控制里加「本机 / 其他电脑」开关。从其他电脑访问时，右键菜单里的「用默认程序打开源文件」「在文件夹中显示」换成「下载源文件」。
   - 打开局域网访问时的提醒保留。

8. 历史（ADR-024）
   - 没有版本插件时去掉：关系图里「切到旧版本看当时的关系」、版本页签里「标签与关系」的历史。有版本插件时保留。
   - 校验页签里的「记录」去掉，只显示最近一次的结论：谁、什么时候、意见。打回意见要能在这里看到。

9. 缩略图（ADR-025）
   - 去掉任务页里后台渲染的开关与「等待渲染」的说法。
   - 需要渲染的资产进入视口前显示占位图，进入视口后渲染并替换。

10. 多资产库（ADR-026）
    - 资产库菜单保留「切换资产库…」，做出切换面板：列出已登记的资产库（名称、根文件夹）与「添加资产库…」。切换只影响当前浏览器。
    - 「在访达中显示」改为「在文件夹中显示」。

11. 创建（ADR-016）
    - 评审控制里加「创建插件：有 / 无」。没有时顶栏仍是「上传」按钮；有时变成「新建」菜单，「上传文件…」排第一，后面是插件登记的创建方式。
    - 用一个虚构的第三方插件演示：新建菜单里的「AI 生图…」；选中四视图时右键菜单里的「生成模型…」；由插件声明的参数表单；创建任务出现在任务页与顶栏的后台处理面板里，有进度、可以取消；完成后新资产出现在网格里，生产记录里带插件名、提示词、输入资产及其角色。
    - 一次生成多张只挑一张时，没挑中的不出现在资产库里。
    - 同一个虚构插件顺带演示其余插槽：详情页签、顶栏按钮、左栏分区、设置页，以及依赖的外部工具缺失、插件连续失败时的样子。

12. 快捷键
    - 单键只留空格（快速预览）与 Delete（删除，仍弹确认）。其余单个字母、数字的快捷键全部去掉，包括 1、2、3 改阶段、T 打标签，以及对比页、校验队列里的单键。要保留的功能改成带 Ctrl（Mac 上是 ⌘）的组合键，或者只用鼠标。
    - 方向键、回车、Esc 保留。
    - 全局撤销用 Ctrl+Z（Mac 上是 ⌘Z），只管本次打开期间的操作。
    - 界面上显示的快捷键提示同步修改。

13. 其他小项
    - 删除任何资产都弹确认，有没有被引用是确认框里的一句提示。这是现状，不要改成不确认。
    - 回收站默认保留 7 天，所有写着 30 天的地方改掉；保留天数在资产库设置里。
    - 标签管理从设置里拿出来，在左栏放一个入口，独立成页。

【二、要对齐的：原型与文档说法不一样的地方】
- 端口统一为 7420。
- 缓存位置是资产库里的 .bowerbird/cache/。
- 定时扫描每 10 分钟一次。
- 任务有 8 个阶段，补上「派生」。
- 去掉 Lore「支持文件锁」的说法。
- 排序项与搜索语法以 search.md 为准。

【三、要补的：文档里有、原型没画的界面】
逐条对应审查报告的 F-02 至 F-13：
- Agent 接入：设置里的一个分区，有地址、可复制的 MCP 配置、命令行示例。
- 别人或 Agent 造成的变化在页面上怎么出现：有新资产时、正在看的资产被替换时。
- 搜索：相关度与创建时间排序、命中处高亮、筛选项后面的数量、语法补全。
- 智能文件夹：改名、删除、编辑条件、用当前条件更新。
- 文件夹：新建子文件夹、改名（磁盘上的名字与显示名的区别）、删除非空文件夹的确认、移动时遇到同名。
- 导出对话框：打包下载、是否连同引用的资产一起（按 ADR-018 的位置名带出）、保留目录还是拍平、多选导出。
- 检查器里的「描述」分区。
- 「替换为新版本…」的入口（右键菜单与详情页），可以填说明。
- 包式资产：「把这个文件夹作为一个资产」的入口与确认、网格里的样子、包内文件列表。
- 第一次打开一个已经有文件的文件夹：说明会在每个文件旁边写 .bmeta、全量认领的进度、缺少插件的资产库。
- 上传：选择目标文件夹、将继承的默认值、失败、重试、取消；拖入文件夹时保留目录结构。
- 校验队列、完整性、回收站、设置四个页面的加载中与出错状态。

【四、文案与名称】
- 同一个操作在所有页面用同一个名称、图标、位置。出一张「操作名称表」。
- 文案清单按本次改动更新：7 天、.bmeta、复制的提示条、更换关系、「这个格式不支持」、「未署名」、「下载源文件」等。
- 出一张 Mac 与 Windows 两套的快捷键表。

【五、查漏补缺】
- 逐条过审查报告的 E 节与 F 节。被第 5 节作废的跳过；其余的要么改掉，要么在交付物里写明不改的原因。
- 改完之后自己完整走一遍：四条演示路径、对比页的每一种组合与方式、3D 查看器的各项功能、版本页签有无插件两种形态、设置里每个分区、评审控制里每个开关。
- 走的过程中发现的新问题，能按现有决策判断的直接改，判断不了的写进「待确认」。

【怎么验证】
- 用本地静态服务打开原型，不要用 file://。
- 每改完一组，在浏览器里实际操作一遍对应的流程，确认控制台没有报错。
- 深色与浅色各看一遍；1440 宽与较窄的窗口各看一遍。

【交付物】
1. 修订后的原型（design/prototype/）。
2. 更新后的 design/docs/：pages.md（页面与状态）、components.md（组件与变体）、copy.md（文案清单，含操作名称表与快捷键表）、deviations.md（在「评审中定下的改动」里补上这一轮的条目，并写明每条对应的 ADR）。
3. 一份修订说明，写到 design/review/{日期}-prototype-revision.md，中文，包含：
   - 改了什么：按上面一到四的编号逐条写做了没有。
   - 没做的：哪几条没做、为什么。
   - 审查报告 E、F 两节逐条的处理结果。
   - 待确认：拿不准的问题，每条给出你的倾向和理由。
   - 验证：实际操作了哪些流程，哪些没有验证。

【原则】
- 每一条都要对得上依据：ADR 编号、审查报告的条目编号、或功能文档的章节。
- 没验证过的写「未验证」，不要说成做完了。
- 流程尽量不要人工步骤（ADR-013）。
- 内核不认识任何文件格式、AI 服务或版本控制系统；原型里凡是演示这类能力的地方，都要看得出它来自插件。
```
