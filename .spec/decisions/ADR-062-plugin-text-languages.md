# ADR-062：插件文字的多语言：清单按原文给译文，服务端写下的文字由插件网页部分按语言说出

状态：Accepted
日期：2026-11-26

## 背景

- ADR-061 定了界面多语言：语言是一张表，缺的文字按英文、中文顺序回退。
- 插件的文字分三类，各有难处：
  1. **网页部分自己的文字**，在插件代码里。
  2. **交给外壳显示的文字**：插件名、格式名、设置项、创建方式与动作的名字和参数表单、界面插槽标题、任务消息。有的写在清单里，有的是 `activate()` 运行时才登记的。
  3. **服务端写下、外壳显示的文字**：提取时写进索引的网格角标（「2,480 面」）、校验器写下的检查说明。
- 内核不能认识任何格式（ADR-003），也不能替插件翻译。

## 决策

**网页部分自己的文字**
- 用插件开发包的 `defineMessages` / `useMessages` / `translate` / `pageLocale`。
- 中文必有，其他语言可选，按 ADR-061 回退。

**交给外壳显示的文字**
- 清单加可选的 `l10n`：语言 → 原文 → 译文；另加可选的 `sourceLocale`，表示插件用什么语言写原文，默认简体中文。
- 按原文查，所以运行时才登记的文字也能翻，内核不用给每段文字起标识。原文可以带 `{name}` 占位符，匹配会变的消息（「生成中 {pct}%」）。
- 内核只把这两个字段原样带到 `PluginInfo`，由外壳按当前语言显示。没有译文的文字照原样显示。
- JSON Schema 的下拉选项支持 `enumNames`（或 `x-enumNames`）作为显示名，同样可翻。

**服务端写下的文字**
- 服务端照旧用原文写一份。
- 插件的网页部分可以提供两个钩子：
  - `FormatView.formatBadge(badge, locale)`：网格角标；
  - `WebPlugin.validators[校验器标识].label / message(check, locale)`：校验说明。
- 外壳显示前先问钩子；钩子没有、返回 null 或出错时显示原文。两头都在同一个插件里，内核仍不认识格式。

**测试**
- 插件开发包的测试工具检查：每种语言的键与占位符；清单与登记的文字都有译文。
- 检查对照 `LOCALES`，以后加语言会自动检查到。

## 不做的

- 写进资产库的数据不翻：Agent 摘要、生产记录里的角色与工具名。
- 浏览器渲染失败时交回的原因，按那台浏览器当时的语言保存；要按看的人的语言显示，需要结构化的错误码，第一期不做。

## 理由

- 按原文查，插件作者只写一张对照表，不用改代码结构；旧插件不写 `l10n` 也照常工作。
- 服务端不知道看的人用什么语言，由网页部分在显示时转换，比给每个请求带语言更简单，也不让内核碰格式。

## 影响

- 清单与 `PluginInfo` 各加两个可选字段；网页接口加两个可选钩子。
- knowledge/features/plugin-system.md、builtin-plugins.md、web-shell.md；docs/plugin-development.md。
