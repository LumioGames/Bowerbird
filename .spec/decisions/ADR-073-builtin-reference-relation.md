# ADR-073：内置关系增加「参考」，对方变了不提醒

状态：Accepted
日期：2026-11-27

## 背景

- 内置三种关系：来源、引用、归属（ADR-005）。每种关系类型有一个开关，决定对方内容变了要不要登记「上游已更新」；内置的只有「来源」开着。
- 「来源」现在装了两种意思：
  - 照着它做出来的，例如从图集拆出的单图、照四视图建的模型。上游变了，下游多半要重做。
  - 只是看了一眼做参考，例如照原型截图出效果图。上游变了，下游不用动。
- 一次真实项目接入的使用反馈（2026-11-27）：原型截图重截之后，照它出的 89 张效果图全部报「上游已更新」，一直挂在问题清单里。截图随时能重截，这些提醒是噪音。

## 决策

- 增加第四种内置关系「参考」，反向叫「被参考」。它不跟踪对方的版本：对方内容变了，不登记「上游已更新」。
- 追溯与关系图里照样显示参考关系；追溯默认走来源与参考两种。
- 登记时由人或 Agent 说明是来源还是参考。没说明时按来源，与现在一样。
- 已有的来源关系不自动改；要改成参考，由人或 Agent 更换关系类型。

## 替代方案与否决理由

- **在每条来源关系上加一个「不提醒」的标记**：同一件事就有了两套开关，一套在关系类型上，一套在单条关系上。类型上的开关内核里已经有，「上游已更新」就是按它算的，加一种关系不需要新机制。
- **只在命令行补上批量「确认已复核」**：每重截一次截图还是要确认一次。命令行会经 [ADR-071](ADR-071-one-definition-for-cli-and-mcp.md) 得到批量处理，但那解决的是「怎么消掉」，不是「不该报」。
- **按输入的角色判断**（角色写着「参考图」就不提醒）：角色是插件自己起的名字，内核认不出哪些算参考。

## 兼容影响

- 改口 [ADR-005](ADR-005-assets-and-typed-relations.md) 的一句：内置关系从三种变为四种。其余各条不变。
- knowledge/features/data-model.md：关系类型表。
- knowledge/features/sync-and-integrity.md：对账规则 R12 的适用范围不变（来源，以及声明要跟踪版本的类型），补一句参考不在其内。
- knowledge/features/api-and-agent.md：追溯默认的关系类型。
- knowledge/features/web-shell.md：关系图的图例、建立关系时的类型选单。
- 内核里内置关系表有两处（`packages/core` 的服务与插件登记），要一起加。

## 实现时要定的

- 「参考」的标识（英文名）。
- 复制资产时参考关系是否跟着带走（来源与引用现在的做法见 ADR-005）。
