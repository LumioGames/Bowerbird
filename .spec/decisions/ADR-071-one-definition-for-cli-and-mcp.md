# ADR-071：每个能力只定义一次，命令行与 MCP 都从这份定义生成

状态：Accepted
日期：2026-11-27

## 背景

- 内核的能力通过接口提供。接口之上，命令行（`packages/cli`）与 MCP（`packages/mcp`）是两份各自手写的代码，网页是第三份。
- 每加一个能力要在几处各补一遍，漏一处就对不齐。一次真实项目接入的使用反馈（2026-11-27）里的几条都是这样来的：
  - 生产参数 MCP 能传，命令行的 `bb add` 没有这个参数；
  - 批量处理完整性问题，接口与网页都有，命令行没有；
  - 命令行的输出借用了 MCP 那份英文文字，而 ADR-061 定的是命令行与 MCP 的输出只有中文。
- 这些单独看都是小疏漏，但只要还是手写几份，以后每加一个能力都会再漏。

## 决策

- 每个能力只定义一次，写明：名字、参数、说明、输出的文字。
- 命令行的命令与 MCP 的工具都从这份定义生成，不再各自手写。同一个能力在两处的参数与输出文字相同。
- 网页是界面，仍然单独做，调用的是同一批能力。
- 插件登记的创建方式与动作也进这份定义，自动出现在命令行与 MCP 里。内核不为某个插件单独补命令。
- 输出文字的语言照 ADR-061：只有中文。
- MCP 仍然不提供删除（现有约定），由定义里标明哪些能力不给 MCP。

## 替代方案与否决理由

- **保持手写，把这次漏的几处补齐**：最快，但下一个能力还会漏。
- **命令行只留一条通用命令，直接转发接口请求**：不会漏，但使用者要自己拼请求，帮助文字与参数校验都没有。
- **只留 MCP，不要命令行**：这次反馈的使用者以命令行为主；命令行也是人排查问题时用的入口。

## 兼容影响

- 改口 [ADR-050](ADR-050-distribution-and-cli.md)：命令的清单与参数不再在 `packages/cli` 里逐条写；环境变量、主包结构、`bb serve` 的规定不变。
- knowledge/features/api-and-agent.md：命令行一节与 MCP 工具表改为同一张能力表。
- knowledge/features/plugin-system.md：创建方式与动作怎样出现在命令行与 MCP。
- knowledge/features/engineering.md：包划分里 `packages/cli` 与 `packages/mcp` 的职责。
- README.md 与 docs/usage.md 里的命令示例。
- 代价：
  - 生成的命令写法统一，不如手写的顺手，现有命令的写法（例如 `bb add <文件…>`）可能要变。
  - 现有的命令行与 MCP 代码基本重写。

## 实现时要定的

- 定义放在哪个包、用什么形式写。
- 定义与 HTTP 接口的关系：接口也从它生成，还是只有命令行与 MCP。
- 生成的命令怎么命名、位置参数怎么安排，哪些旧写法保留。
