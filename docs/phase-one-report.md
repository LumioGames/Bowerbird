## 三、性能（十万资产）

`node tests/perf/run-perf.mjs`，Apple M5（10 核，17 GB），Node 22.23。生成的资产库：十万资产，401,458 个文件，415 MB。完整跑了三轮（两轮带网页，一轮 `--skip-web` 只测服务端），修复重启扫描后又跑了一轮 `--skip-web`，下表写各轮的范围；最后一轮的原始数字在 `tests/perf/results.json`（不进仓库）。

| 项目 | 结果 | 目标 | |
|------|------|------|------|
| 首次建索引 | 126–151 秒 | 以算指纹的速度为上限 | 见下方说明 |
| 建完后常驻内存 | 163–307 MB | — | |
| 稳定后常驻内存 | 149–264 MB | 500 MB 以内 | 达标 |
| 结构化筛选（中位数） | 2.5–40 毫秒；最慢一轮 p95 143 毫秒 | 100 毫秒以内 | 中位数达标，最慢一轮的 p95 超出 |
| 按文件夹筛选（中位数） | 43–77 毫秒 | 100 毫秒以内 | 达标 |
| 关键词搜索（中位数） | 2.1–28 毫秒 | 200 毫秒以内 | 达标 |
| 分面统计（中位数） | 74–80 毫秒 | — | |
| 单个文件变化到事件发出 | 2,718 毫秒 | 2 秒内 | **未达标**：扫描器要等文件 2 秒不变才算写完（防止处理到复制一半的文件，sync-and-integrity.md），这个等待本身就占了 2 秒。目标与稳定性判断要二选一，需要定 |
| 重启后的增量扫描 | 13.9 秒（修复前 261–284 秒） | 30 秒以内 | 修复后达标，见下方说明与 ADR-065 |

| 网页首屏 | 459–586 毫秒 | 打开浏览页到首屏可见 1 秒以内（web-shell.md）；首屏结果渲染 500 毫秒以内（search.md） | 前者达标；后者有一轮超出 |
| 网格滚动 | 60.5–61 帧 | 60 帧 | 达标，但十万资产时缩略图还没生成，滚的是占位格 |
| 切换文件夹 | 十万规模没测出结果；2,000 资产：中位数 65 毫秒，最慢 443 毫秒 | 300 毫秒以内 | 只在小库上测过，最慢一次超出 |
| 快速查看一张图 | 十万规模没测出结果；2,000 资产：7 毫秒 | 200 毫秒以内 | 只在小库上测过 |

说明：

- 重启后的增量扫描：原来比首次建索引还慢，原因是重启时管线先接着做上次没做完的任务（并发为核心数减一），和扫描抢同一个事件循环、线程池和写锁，扫描的每一步都慢了 5–7 倍；另外对账时每个资产的元数据文件都要重新读一遍。改成全库扫描时管线让路（只做界面可见的，一次一个）、没变的元数据文件不再读（ADR-065）。修复后在后台排着约 76 万个任务的情况下单独测是 15.8 秒，性能脚本里是 13.9 秒。
- 首次建索引按字节算只有每秒约 3 MB，瓶颈不在算指纹，而在每个文件的处理上（40 万个文件，平均每个约 1 KB）。
- 2,000 资产、缩略图都生成好以后，无头浏览器里滚动只有 16.5 帧：无头 Chromium 用软件绘制，这个数字不代表有显卡的真实浏览器，但真实浏览器里也没有实测。
- 切换文件夹与快速查看：测试脚本原来按格式筛选找资产，十万资产时后台处理还没给文件标上格式，所以找不到；已改成直接从磁盘挑文件（本次提交），改后只在 2,000 资产上跑过。
- 另外：十万资产首次打开的常驻内存峰值 295 MB（改前 543 MB）；计数与任务概览 50 毫秒以内；十万资产入队 37 毫秒。查询、关键词搜索、分面的计时断言在 `pnpm test:bench` 里，全部通过。

## 五、与原型仍有的差别

| 差别 | 原因 |
|------|------|
| 左栏底部三个按钮只有图标：「设置」在左下角，「标签」「任务」在右；「任务」是显示后台状态的小圆环 | 你在走查时定下（deviations.md 第五类） |
| 网格悬停转台是模型自己转，相机不动 | 你在走查时指出「像相机在动」，改成与原型 `model.js` 一致 |
| 数量、时间、文件大小、三角面数等都是真实值，与原型里写死的数不同 | 原型是示意数据；样例资产库由原型数据生成，名字与结构一致，数值以真实文件为准 |
| 没有原型左下角的「图层」评审控制（版本插件状态、四条演示路径） | 交付说明：评审工具不进产品 |
| Forge 创建插件只在测试里出现，不随产品发布 | 交付说明：Forge 改成测试用插件 |
| 没有「活动」面板 | ADR-040 |
| 触屏上没有悬停转台 | ADR-032 |
| 以图搜图的入口不由外壳画 | ADR-039，由语义搜索插件提供；第一期没有语义搜索插件 |
| `.hdr`、OBJ 显示为未知格式 | 第一期没有对应插件（builtin-plugins.md） |
| 版本页签的「标签与关系」筛选、按版本看历史关系图不可用 | 需要版本或历史插件提供「按版本取关系与元数据历史」的接口（versioning.md 待解决） |
| 顶栏不显示版本存储的同步状态 | 外壳还不调用 `status()`；第一期没有版本插件 |
| 给 Agent 的资产摘要、命令行与 MCP 输出只有中文 | 界面有中、英、日、韩四种语言（ADR-061）；摘要、命令行与 MCP 主要给 Agent 用，第一期只写了中文 |
| 演示路径②的关系图是 9 个节点，原型画了 10 个 | 样例库按原型数据生成，chest_concept.png 没有上游，按数据只有 9 个（deviations.md 第六类） |
| 设置页「插件设置」下只列有设置项的插件 | 没有设置项的插件点进去是空页（deviations.md 第六类） |
| 3D 查看器的「查看选项」多一行「色调」（ACES、AgX、中性、无） | builtin-plugins.md 要求色调映射可选；功能文档优先于原型（deviations.md 第六类） |
| 检查器的技术信息多一行「目标尺寸」 | 设计对象写了目标尺寸时外壳显示出来，方便对照；原型的检查器没有这一行 |
| 左栏底部的任务圆环细、小、颜色淡 | 你定下：这个东西本身不重要 |

截图对比的结论：12 个场景、深浅两种主题、1440 与 1100 两种宽度，可见文字与界面结构都与原型一致；上表与 `e2e/tests/b-screens.spec.ts` 的 `KNOWN` 表列出了全部允许的差别，表外出现新差别测试就会失败。

## 六、已知问题与没做的

- 单个文件变化到事件发出要 2.7 秒，超出「2 秒内」的目标：2 秒的稳定性等待是故意的，目标和它冲突，要定留哪个（第三节）。
- 切换文件夹、快速查看只在 2,000 资产上测过；有缩略图时的滚动帧率没有在有显卡的浏览器里测过（第三节）。
- Docker 镜像没有构建：这台电脑没有 Docker 守护进程，`Dockerfile` 只做了静态检查。
- 资产库声明了、但这台电脑没装的插件，只能显示插件标识（如 `community.spine`），没有显示名：library.json 里没有放名字的地方，要加 `pluginNames` 需改磁盘格式（新 ADR），第一期没做。
- 只在 macOS 上跑过：单元测试、浏览器测试、性能基准都在这台 Mac 上。Windows、Linux 没有实测（Linux 的按目录监听有单元测试）。浏览器测试只用 Chromium；Firefox、Safari 没有实测。
- 超大图片的上限（任一边超过 32767 像素，或解码后超过约 5 亿字节）参照 Firefox 的限制定的，没有在 Firefox、Safari 里实测。
- 版本插件（Lore、Git LFS）不在第一期：版本时间轴、按版本的「标签与关系」筛选、历史关系图、顶栏的同步状态都要等它。
- `⌘A` 只选中已经加载出来的结果；按查询整批选中还没接上（web-shell.md 待解决）。
- 浏览器渲染失败时交回的原因，按那台浏览器当时的语言保存；别人用另一种语言打开时看到的是那种语言（ADR-062「不做的」）。
- 窗口窄于约 900 像素时，浏览页工具栏最右侧的按钮仍会被截掉（1100 及以上都放得下）；3D 查看器自己的工具栏在 1100 宽的日文、韩文下，「完整渲染」「出图」会折行。
- 测试插件 Forge 自己接口返回的报错只有中文（它只用于测试）。
- npm 的 `@bowerbird` 作用域是否归你所有没有核实：`bowerbird` 与 `@bowerbird/core` 两个名字查询时未被占用，发布前要先在 npm 上建 `bowerbird` 组织。

## 七、仓库、发布与下一步

### 1. 仓库（已推送）

- 公开仓库 `github.com/LumioGames/Bowerbird`，`main` 从一个干净的提交「Bowerbird 0.1.0」开始，之后是这份报告补数字的提交：测试用的样例资产不在里面，下载下来是干净的。
- 完整的开发历史（几百个提交）留在本机分支 `dev-history`，没有推送。
- 改本地目录名（可选），关掉正在用这个目录的会话与编辑器后：

```bash
mv ~/ArtEnv/LGArtStudio ~/ArtEnv/Bowerbird
```

### 2. 下一期先谈的：新手引导

- 你提出的功能介绍与新手引导（各功能是做什么的、遇到新文件时的提示）还没有做，按「先谈设计再写代码」放到下一期第一项（ADR-063「不在这一条里」）。
- 这一期已经有的是第一步：没有资产库时的欢迎页，「打开文件夹」「新建资产库」。

### 3. 发布 npm 包

先在 npm 上登录（`npm login`），并建好 `bowerbird` 组织，让 `@bowerbird` 作用域归你。然后在仓库根目录、干净的 main 上：

```bash
pnpm install && pnpm build
pnpm --filter @bowerbird/schema publish --access public
pnpm --filter @bowerbird/plugin-sdk publish --access public
pnpm --filter @bowerbird/plugin-build publish --access public
pnpm --filter @bowerbird/core publish --access public
pnpm --filter @bowerbird/server publish --access public
pnpm --filter @bowerbird/mcp publish --access public
pnpm --filter @bowerbird/cli publish --access public
pnpm --filter bowerbird publish
```

- 顺序不能乱：后面的包依赖前面的。pnpm 发布时把 `workspace:` 依赖换成实际版本号。
- 六个内置插件不单独发布，它们打在 `bowerbird` 主包里（打包前自动复制）。
- 发布后验证：在一个空文件夹里 `npx bowerbird@0.1.0 serve ./试用库`。
- 使用者安装 `bowerbird` 时装 220 个包、约 118 MB，不含构建工具与 React；拆分前是 348 个包、约 280 MB。

### 4. Docker 镜像

```bash
docker build -t ghcr.io/lumiogames/bowerbird:0.1.0 -t ghcr.io/lumiogames/bowerbird:latest .
echo "$GITHUB_TOKEN" | docker login ghcr.io -u <你的 GitHub 用户名> --password-stdin
docker push ghcr.io/lumiogames/bowerbird:0.1.0
docker push ghcr.io/lumiogames/bowerbird:latest
```
