# 开发提示词：照原型把 Bowerbird 做成正式版本

把下面整段交给新的会话（在仓库根目录）。

---

你要把 Bowerbird 第一期从设计文档和交互原型做成可以发布的正式版本。**整个过程不要问我**：遇到文档没写的地方，按下面「自己拿主意的规则」决定并记录，然后继续；做完、测完、自己走完整套流程再交回。只有两件事留给我：推送到远程仓库、发布 npm 包或 Docker 镜像——这两件不要做，在交回里写明怎么做。

## 一、先读什么（按顺序）

1. `CLAUDE.md`、`.spec/AGENTS.md`、`.spec/knowledge/README.md`、`.spec/rules/system.md`。
2. `.spec/decisions/README.md` 与全部 ADR。ADR-014、ADR-015 已被 ADR-019、ADR-020 取代，ADR-004 已被 ADR-017 取代；以新的为准。
3. `.spec/knowledge/features/` 全部功能文档，从 `overview.md` 读起；工程结构以 `engineering.md` 为准。
4. `design/README.md`，然后 `design/docs/pages.md`（每个页面和它的全部状态）、`design/docs/components.md`（组件与变体）、`design/docs/copy.md`（全部文案、操作名称表、快捷键表）、`design/docs/deviations.md`（原型相对最初提示词的改动及依据）。
5. `design/review/2026-11-25-review.md` 第 5 节，和 `design/review/2026-11-25-prototype-revision.md`（原型修订说明，含 E、F 各项的处理与「待确认」的倾向）。
6. `design/prototype/` 的源码，并用本地静态服务打开原型逐页操作一遍：`python3 -m http.server 4793 --directory design/prototype`，访问 `http://localhost:4793/index.html`。左下角「图层」按钮里的演示路径和状态开关能把每个状态都调出来。
7. `design/design-system/`（`tokens.json` 与组件样式）。

## 二、以什么为准

- **行为与数据**以 `.spec/` 为准：磁盘格式、对账规则、接口、搜索、插件扩展点、执行者、版本记录。
- **界面**以原型为准：结构、布局、每个状态、交互、动效、文案。`design/docs/copy.md` 里的文字照抄，操作名称表里的名字、图标、位置不能改。原型里没有说明文字的地方，正式版也不加。
- **视觉**以设计系统为准：`tokens.json` 的颜色、间距、圆角、字体、动效时长转成 Tailwind 主题与 CSS 变量，深色与浅色两套都要。
- 原型是 HTML + 原生脚本写的，**照搬的是界面结构、状态、文案和交互规则，不照搬写法**。正式版按 `engineering.md`：TypeScript 严格模式、pnpm 工作区、Fastify、SQLite、React、Vite、shadcn/ui、Magic UI、Tailwind、three.js、TanStack Query、Vitest、Playwright（ADR-010、ADR-021）。
- 两者冲突时：ADR > 功能文档 > 原型修订说明 > 原型 > 设计系统示例页。

## 三、做什么（第一期范围，`overview.md`「分期」）

- `packages/`：`schema`、`core`、`server`、`plugin-sdk`、`web`、`cli`、`mcp`，依赖方向按 `engineering.md` 的表，两条硬约束不能破：内核不引用任何具体插件；插件只依赖 `plugin-sdk` 与 `schema`。
- `plugins/`：图片、视频、音频、3D 模型（GLB、glTF、FBX；OBJ 按未知格式）、文档、关键词搜索。
- 网页外壳的全部页面与状态：以 `design/docs/pages.md` 为清单逐项实现。
- Agent 接口：HTTP API、事件流、MCP、命令行 `bb`（`api-and-agent.md`）。
- 插件扩展点全部定好接口；创建（ADR-016）的登记通道与生产记录格式第一期必须做；访问控制与改动通知只留位置。
- 界面插槽全部做出来：新建菜单（有创建插件时取代「上传」）、右键创建项、参数表单、详情页签、顶栏按钮、左栏分区、检查器分区、插件设置页、缺少外部工具与连续失败的提示。
- 版本：内核的版本记录与「版本存储」扩展点；没有版本插件时的界面（只记录、说明、「选择版本插件…」）。Lore 与 Git LFS 插件不在第一期。

**不做进产品的**：原型左下角的「图层」评审控制；虚构插件 Forge（`design/prototype/plugin-demo.js`）。Forge 改写成 `fixtures/plugins/` 下的测试插件（不随主包发布），用来验证创建扩展点和每一个界面插槽；它调用的 AI 服务用本地假实现代替，不访问任何外部服务。

## 四、怎么组织（并行）

你是主 loop：负责拆分、派活、合并、审查和最终验收；子 Agent 只执行，不再派生子 Agent。

1. **搭骨架并冻结接口（串行，主 loop 自己做）**：工作区、TypeScript 与构建配置、测试框架、Tailwind 与 shadcn/ui 初始化、设计变量；`packages/schema` 写全（`.bmeta`、`_folder.bmeta`、`library.json`、查询模型与文本语法、全部接口的请求与响应、事件、插件清单与扩展点类型）；`packages/plugin-sdk` 的类型。冻结后提交，后面所有工作只以它为接口依据，不等上游实现。
2. **并行开发**：按目录互不重叠拆成多条线，每条线一个子 Agent，各自在独立的 git worktree 里做（Agent 工具用 `isolation: "worktree"`），可以同时开多个会话。建议的线：
   - 内核：资产库读写、扫描与对账（R1–R12）、关系与完整性、回收站、复制移动删除的语义。
   - 内核：任务管线（8 个阶段）、缓存键与清理、SQLite 索引与全文检索、查询解析与融合、插件宿主与安装（npm 包名或本地路径）。
   - 服务：HTTP API、错误模型、事件流、缩略图交回、多资产库路由；命令行；MCP。
   - 网页外壳一：框架、左栏、顶栏、网格 / 瀑布流 / 列表、检查器、筛选与搜索（语法补全、分面、命中片段）、上传、导出、文件夹与智能文件夹、资产库切换与首次打开、提示条与对话框、快捷键与撤销。
   - 网页外壳二：详情页、关系图（更换对方、位置名）、版本页签、校验页签、校验队列、完整性、回收站、标签页、设置（含 Agent 接入）、对比页框架（卷帘分界线、方式与不可用原因、技术信息表）。
   - 内置插件：图片、视频、音频、文档、关键词搜索（含各自的查看器与对比）。
   - 3D 插件：查看器全部功能（通道与分量、顶点色 R G B A、读不出的通道提示、卷帘与斜切、正交、视图方块、环境与灯光、动作、尺寸与比例尺、出图）、模型对照四视图（按格子、尺寸线、5% 宽高比）、尺寸检查、网格悬停转台、页面懒渲染缩略图。
   - 测试数据：`fixtures/` 里的样例资产库，复刻原型的「星落镇」（`design/prototype/data.js` 的资产、文件夹、关系、生产记录、问题与回收站），每个文件都用脚本生成（图片用 sharp 画、模型用 three.js 或 glTF 工具导出、音频合成、文档直接写），保证能随开源项目分发；再写十万资产的生成器给性能基准用。
   每条线交回时：分支、提交号、跑了哪些测试和结果。主 loop 收到后先看 diff 再合并，冲突退回给那条线。
3. **每合并一批，派一次只读的对抗审查**（插件自带的 `reviewer` 子 Agent，或另开一个只读会话），审完的问题由主 loop 修或退回。
4. 仓库还没有绑定 Workflow 线上项目：拆单写成本地草稿（`.workflow-drafts/`），不上传；如果到时已经绑定，就按插件规程建单、流转和回写。

## 五、自己拿主意的规则

- 文档没写、原型也没画的：先找最接近的已有决定照着做；找不到就选更少人工步骤、更不容易丢数据的做法（ADR-013），并在 `.spec/decisions/` 新增一条 ADR（状态写「提议」），注明是实现时补的，然后继续。
- 修订说明「待确认」里的十项，按其中写的倾向做，并各记一条 ADR（提议）。
- 不得改写已接受的 ADR；功能文档只描述做成后的现状，改了就同步改（用 `spec-steward` 技能，改完跑 `/workflow:lint`）。
- 不加文档和原型里都没有的功能。

## 六、自己测试

按 `engineering.md`「测试策略」全部做到，并且：

- **对账**：R1–R12 每条至少一个集成测试；复制的每条语义（副本名 `_1`、新身份、待审、版本从头、带走依赖、来源记录、引用仍指向原件）；被引用资产的删除与恢复；清空索引后重建与重建前一致。
- **插件契约**：同一套契约测试跑遍六个内置插件和 Forge 测试插件。
- **接口**：每个端点的正常与错误码；多资产库路径；Agent 搜索范围。
- **浏览器（Playwright）**：
  - 原型的四条演示路径、「首次打开已有文件的文件夹」、「别人的改动」、复制后在关系图里更换对方、FBX 读不出通道的提示、远程访问时的「下载源文件」，各写一条端到端测试。
  - `design/docs/pages.md` 里的每个状态至少有一个测试能把它调出来并断言关键文字（文字以 `copy.md` 为准）。
  - 对比的每种组合与方式、不可用时的提示；3D 的主要功能。
  - 截图比对：在同样的样例库和状态下，把正式版和原型（用本地静态服务打开）各截一张，深色与浅色、1440 与 1100 宽，逐张看差异，结构、文字、状态标记要一致，视觉差异只允许来自 shadcn/ui 与 Tailwind 的实现细节。
  - 只用键盘走完每个对话框；用 axe 检查无障碍。
- **性能**：十万资产样例库跑 `engineering.md`、`search.md`、`web-shell.md` 里的全部性能目标，结果写进交回。
- 测试不过就修到过；不得删断言、放宽条件或改基线来变绿。

## 七、做完的标准

- `pnpm install && pnpm build && pnpm test` 全绿；`pnpm e2e` 全绿；性能基准有数值。
- `node packages/cli/dist/index.js serve fixtures/xingluo`（或打包后的 `npx bowerbird serve fixtures/xingluo`）能打开，你自己用浏览器把原型的全部页面和状态对着走一遍，逐项对照 `design/docs/pages.md` 打勾。
- `.spec/` 已同步：功能文档的状态与内容、新增的 ADR、`AGENTS.md` 的收口命令；`/workflow:lint` 的结果附在交回里。
- 本地提交整洁（按线分支合并进 `main`，提交说明写清楚做了什么）；不推送、不发布。

## 八、交回

用中文写一份 `docs/phase-one-report.md` 并在最后的回复里给出要点：做了什么（按包和页面）、每类测试跑了什么和结果（附命令与关键输出，没跑的写「未执行」）、性能数值、新增的 ADR 列表、与原型仍有差异的地方及原因、推送与发布要我执行的命令。
