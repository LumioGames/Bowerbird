# ADR-045：判定重复身份的原件时，名字像副本的一份是副本

状态：提议
日期：2026-11-25

## 背景

两份元数据文件带着同一个 GUID 时，要判定哪一份是原件（sync-and-integrity.md「重复身份」）：路径与索引记录一致的是原件；索引里没有记录时，文件创建时间更早的是原件，时间相同则路径字典序靠前的是原件。

做样例库时发现后两条在常见情况下会判反：`git clone`、`cp`、云盘同步都不保留文件的创建时间，复制出来的文件创建时间可能更早；`btn_buy (1).png` 按字典序排在 `btn_buy.png` 前面（空格小于点）。判反的后果是引用跟着副本走，原件反而换了新身份。

本条是第一期实现时按 ADR-013 补的，待评审。

## 决策

索引里没有记录时，按以下顺序判定原件：

1. 去掉常见的副本后缀（` (1)`、` (2)`…、` copy`、` - Copy`、` 副本`、`_1`、`_2`…）后与另一份同名的那一份是副本，另一份是原件。
2. 否则文件创建时间更早的是原件（拿得到可靠创建时间的文件系统上）。
3. 再否则路径字典序靠前的是原件。

判定结果照旧登记为问题请人确认，界面上可以对调（「其实这个才是原件…」）。

## 替代方案与否决理由

- **只按创建时间**：多数复制方式不保留创建时间，结果接近随机。
- **只按路径字典序**：`(1)` 这类后缀反而排在前面。

## 兼容影响

- knowledge/features/sync-and-integrity.md「重复身份」的判定顺序。
