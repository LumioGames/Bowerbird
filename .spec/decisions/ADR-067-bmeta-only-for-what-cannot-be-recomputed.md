# ADR-067：元数据文件只在有了算不出来的信息时才写

状态：Accepted
日期：2026-11-27

## 背景

- 现在扫描器看见一个文件，就给它一个 GUID，并在旁边写一份 `.bmeta`（ADR-017）。
- 一份刚写出来的 `.bmeta` 里只有 GUID 和内容指纹。指纹可以重算；GUID 只有在别的资产引用它时才有意义，而这时还没有任何资产引用它。也就是说，这份文件里没有任何重建不出来的东西，却被写进了作为唯一真值的磁盘。
- 一次真实项目接入的使用反馈（2026-11-27）里，好几个问题都从这一步来：
  - 初始化一个混着脚本、网页原型和说明文档的美术文件夹，一次写出三百多个 `.bmeta`；
  - 之后补上忽略规则，已经写出去的收不回来，变成「文件缺失」错误；
  - 扫描器先认领，Agent 再登记，说不清「已登记」指的是哪一步；
  - 资产库放在 git 仓库里时，看文件夹和看改动有一半是 `.bmeta`。

## 决策

**两种信息**
- 关于一个文件的信息分两种：
  - **能从文件自己算出来的**：文件名、大小、格式、宽高或时长这类技术信息、内容指纹、缩略图。丢了重新扫一遍就回来。
  - **算不出来、只能有人告诉的**：标签、描述、阶段、关系、出处、校验结论、版本记录、手动指定的缩略图、四视图的格子、自定义字段。这里的「有人」包括人和 Agent。AI 自动打的标签与描述也算这一种，因为重新生成要花钱，结果还可能不同。
- `.bmeta` 只用来存第二种信息。

**什么时候写**
- 一个文件只是被扫描器看见时，只进索引，不写 `.bmeta`。它照样能浏览、搜索、预览、生成缩略图。
- 第一次有第二种信息要记下时，才写 `.bmeta`，同时写入 GUID。
- 一个文件被别的资产的关系指向时，也写它的 `.bmeta`：这时它的 GUID 有了意义。
- 初始化资产库不在文件旁边写任何东西。

**「登记」的意思**
- 「登记」只有一个意思：有人给这个文件记下了第二种信息。扫描器看见文件不叫登记。

**忽略规则改了之后**
- 没有 `.bmeta` 的文件被忽略规则命中：直接从索引里消失。
- 有 `.bmeta` 的资产被忽略规则命中：自动移出资产库。文件本身不动，`.bmeta` 移入回收站，可以恢复。引用它的资产显示断链，与删除资产时一致。
- 命令行和接口提供「移出资产库、不动文件」，手动做同样的事。

## 替代方案与否决理由

- **保持每个文件都写 `.bmeta`，只补忽略规则的处理和初始化前的预告**：能止住最显眼的两个问题，但没有信息的文件仍然落盘，放进 git 仓库时照样满是 `.bmeta`，「已登记」的含义也仍然说不清。
- **每个文件夹一份汇总的元数据文件**（反馈的建议）：文件数少了，但两个人改同一个文件夹里的不同资产就会冲突，文件移动时元数据也跟不走。ADR-004 已否决过。
- **默认忽略代码、依赖和构建目录**（反馈的建议）：游戏资产里代码和着色器也可能是资产。不写 `.bmeta` 之后，它们留在索引里也不碍事。

## 兼容影响

- 改口 [ADR-017](ADR-017-bmeta-sidecar-suffix.md) 的一句：「每个资产旁边放一份同名加 `.bmeta` 后缀的元数据文件」改为「有了算不出来的信息的资产旁边才放」。后缀、目录布局、包式资产等其余各条不变。
- knowledge/features/library-format.md：元数据文件一节（何时存在、必填字段）、忽略规则一节。
- knowledge/features/sync-and-integrity.md：
  - 对账规则 R1、R3：新文件没有元数据文件时，不再「生成 GUID、写元数据文件」，只进索引；
  - 忽略规则变化的处理、「移出资产库」。
- [ADR-051](ADR-051-reconcile-and-trash-details.md) 里凡是说「扫描认领」时写元数据文件的细则（例如第一条版本的时间），跟着 R1 一起改。
- knowledge/features/data-model.md：GUID 何时产生、创建时间与创建者的含义。
- knowledge/features/api-and-agent.md：登记的含义、「移出资产库」的接口与命令。
- knowledge/features/web-shell.md：首次打开的说明里不再有「会在每个文件旁边写一个文件」。
- README.md 与 docs/usage.md：初始化一步的说明。
- 代价：
  - 没有 `.bmeta` 的文件被外部工具改名或移动后，会被当成新文件。它身上没有第二种信息，所以什么也不丢。
  - 没有 `.bmeta` 的文件不记创建者，创建时间用文件自己的时间。
- 已有的资产库不需要转换：原来写出的 `.bmeta` 照旧读得出。

## 实现时要定的

讨论时只定了上面的原则，下面几件事留给实现：

- 没有 `.bmeta` 的文件在索引和接口里用什么标识。要求是：Agent 搜到它之后拿这个标识去写信息，写入后 GUID 就是它，不必换号。
- 第二种信息全部被去掉之后（例如删掉了唯一的标签），`.bmeta` 留着还是删掉。
- 文件夹设置给的默认阶段、默认校验状态、默认标签怎么算。现在是认领时抄进 `.bmeta`（R1）；不写 `.bmeta` 之后，是每次按文件夹设置现算，还是到第一次写 `.bmeta` 时再抄进去。
- 已有资产库里只有 GUID 和指纹的 `.bmeta`，要不要提供一次清理。
