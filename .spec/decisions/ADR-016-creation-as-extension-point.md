# ADR-016：创建资产也是扩展点，插件的产出走与接口相同的登记通道

状态：Accepted
日期：2026-11-25

## 背景

[ADR-003](ADR-003-microkernel-and-plugins.md) 定下格式、搜索、AI、版本都是插件，但「资产是怎么来的」只有两条路：人在网页上传，或者库外的工具与 Agent 生成之后调接口登记。后一条路已经能把提示词、参数、输入资产记成生产记录，存在资产库里。

接下来要接的创建流程不止这两种：在界面里用 AI 生图（包括无限画布这类边生成边挑选的流程）、由四视图生成模型，以后还会有别的。它们都依赖具体的 AI 服务，按 ADR-003 只能是插件。对照审查原型与接口草案时（`design/review/2026-11-25-review.md`）发现现有草案接不住：

- 十类扩展点里没有「创建」。入库来源是常驻运行的，不是使用者发起的一次创建；动作是对选中的资产执行操作，文生图没有选中物。
- 插件没有写入通道。插件上下文里资产库是只读的，入库来源与动作用到的 `IngestFn`、`ActionResult` 只有名字，没有内容。
- 任务队列规定一个任务是「一个资产的一个阶段」，创建任务开始时资产还不存在。
- 生产记录的方式是封闭枚举，输入资产没有角色，模型与随机种子没有约定的写法。
- 外壳只有「上传」，没有给插件的新建入口。

## 决策

1. **创建是一类扩展点**，名字就叫「创建」，清单键 `creators`。一个创建方式声明：标识与显示名、参数表单（JSON Schema）、接受哪些输入资产（每项有角色、可接受的格式、是否必需）。内核不认识任何 AI 服务，也不区分「生图」「生成模型」，只知道「这个插件能创建资产」。需要自己界面的创建方式（例如无限画布）用已有的界面扩展点登记页面，页面里调用的是同一个发起接口。
2. **产出只有一条入库的路**。插件把每个产出交给内核登记，内容与 `POST /assets` 的请求相同：文件、目标文件夹、阶段、标签、描述、关系、生产记录。落盘、写元数据文件、写生产记录、建来源关系并记下输入当时的内容指纹、送入处理管线，都由内核完成。入库来源与动作的 `IngestFn`、`ActionResult` 用同一个结构。插件仍然不能直接写资产库。
3. **创建任务是队列里的一类任务**，不绑定资产。插件通过任务上下文报告进度、响应取消；一次运行可以登记零个、一个或多个产出。它和入库处理的任务出现在同一个任务页里。
4. **人和 Agent 都能发起**。创建方式经接口列出、发起、查询，MCP 增加对应的工具。Agent 可以调用库内的创建插件，也可以照旧在库外生成后登记，两种方式留下的记录结构相同。
5. **没挑中的产出是临时文件**。一次生成四张只留一张时，另外三张不是正式资产：放在本机的临时目录里，不进资产库，不跟着同步，可以随时清理。内核不管候选产出，挑中的才登记。
6. **生产记录改六处**（磁盘格式的变化）：
   - `method` 改为开放值。内置值保留；插件自定义的值以插件标识作前缀。
   - `inputs` 的每一项增加可选的 `role`，例如参考图、蒙版、四视图。
   - `params` 约定三个常用键：`model`、`seed`、`negativePrompt`。约定的键可以用来筛选和复现，其余键照旧自由。
   - 增加可选的 `plugin`，值为插件标识加版本，由内核填写；库外登记的记录没有它。
   - 删掉 `outputs`。记录写入后不能改，而产出是之后才逐个登记的，这一项当时填不上；一条记录产出了什么，由「来源关系的 `record` 指向它的资产」反查。
   - 没有任何产出的运行不写生产记录，只留在任务日志里。
7. **执行者记发起的人或 Agent**，不增加新的执行者类别。是哪个插件做的，看生产记录的 `plugin`。
8. **插件创作的文件也是普通资产**。例如画布插件把画布存成库里的一个文件，并作为格式插件认领它。新建走登记，之后每次保存走「替换内容」。设计原则「永不修改原始文件」的含义相应写明确：内核与插件在读取、预览、处理资产时不改资产文件；上传、登记与替换内容本来就会写入资产文件，它们是使用者发起的写入。画布这类文件几秒保存一次时如何合并，由画布插件自己决定，本条不定。
9. **插件的设置项声明自己存放在哪**：随资产库走，还是只在本机。访问凭据一类只能在本机。密钥不写入资产库是工程结构文档已有的规定，这里只是让清单能表达。
10. **外壳的入口**。没有创建插件时，顶栏仍是「上传」按钮；有创建插件时变成「新建」菜单，「上传文件…」排第一，后面是插件登记的创建方式。选中的资产符合某个创建方式的输入时，右键菜单里列出它，例如选中四视图时出现「生成模型」。
11. **分期**。第一期不带任何创建插件。第一期必须做的是第 2 条和第 6 条：前者内置的入库来源与动作就要用，后者是磁盘格式，而且记录写入后不能改。其余几条可以之后再加，接口只增加可选能力时不升主版本。

## 替代方案与否决理由

- **只保留现状：库外生成，再调接口登记**。已经可用，也继续保留。但网页上的人用不了；无限画布这类要在界面里交互的流程接不进来；每个工具自己拼登记请求，提示词与参数的写法不会统一。
- **用动作扩展点承载**：把动作放宽到不需要选中资产，并让它返回新资产。概念少一类，但「对选中项做操作」与「创建新资产」会混在同一个菜单里；输入资产的角色没有地方声明，外壳无法判断某个资产能用来创建什么。两者的任务与登记机制是共用的，分成两类扩展点多出的成本很小。
- **让插件直接写资产库**。接口最省，但绕过对账、校验与留痕，形成第二条写入路径，与 ADR-003「没有私有通道」、[ADR-011](ADR-011-unified-api-and-agent-search-scope.md)「网页与 Agent 共用一套接口」冲突。
- **内核定义「图像生成」「模型生成」等几类生成接口**。界面可以做得更统一，但内核从此认识 AI 服务的种类，每出现一种新的生成方式都要改内核，违反 ADR-003。
- **提示词写进资产的元数据文件**。一次生产有多个产出时要重复写；生产记录已经承担这件事，并且进全文检索。
- **候选产出也登记成资产，或放进包式资产里**。资产库里会堆满没用上的图；候选是过程产物，不值得同步与版本管理。

## 兼容影响

- 本条不取代 ADR-003，是在它列出的扩展点之上增加一类。
- knowledge/features/plugin-system.md 扩展点一览、创建方式的接口、登记结构、设置项的存放位置。
- knowledge/features/data-model.md 生产记录的字段。
- knowledge/features/library-format.md 记录文件的字段。
- knowledge/features/pipeline-and-cache.md 不绑定资产的任务。
- knowledge/features/api-and-agent.md 创建方式的端点与 MCP 工具。
- knowledge/features/web-shell.md 新建入口与插槽。
- knowledge/features/overview.md 设计原则第 4 条的表述、插件层的扩展点列表。
- 交互原型需要补：新建菜单、创建任务在任务页里的样子、右键菜单里的创建方式。
- 已有的生产记录不受影响：新增的字段都是可选的，`method` 的内置值不变。
