# ADR-009：内核不做登录与权限，默认只监听本机

状态：Accepted
日期：2026-11-25

## 背景

项目面向小团队，定位是通用内核。需要决定是否在内核里实现账号、登录、权限分级，以及在不实现的前提下如何保证默认安全。

## 决策

- 内核不实现登录、账号、权限与多租户。需要这些能力的使用者自行二次开发。
- 服务默认只监听本机地址。
- 要让其他机器访问，必须在启动时显式指定监听地址，启动时打印明确警告：任何能访问该端口的人都能读写资产库。
- 文档中写明：不得直接暴露到公网；确有需要时应在前面放置带鉴权的反向代理。
- 服务校验请求的主机头与来源头，防止恶意网页借用户的浏览器访问本机服务。
- 所有删除先进回收站。
- 写操作记录执行者名称，仅用于留痕，不构成访问控制。
- 面向 Agent 的 MCP 服务不提供删除工具。

## 替代方案与否决理由

- **内核提供简单的登录与操作记录**：对团队共用更稳妥，但会把账号体系带进内核，偏离“先做通用内核”的优先级；各团队的身份体系差异很大，适合留给二次开发。
- **默认监听所有地址**：局域网使用更方便，但没有鉴权的服务默认对外开放是不可接受的风险。
- **用一个共享口令做访问限制**：实现简单，但给人以“已有保护”的错觉，实际强度不足以支撑暴露到公网。

## 兼容影响

- knowledge/features/api-and-agent.md 的安全一节与执行者约定。
- knowledge/features/overview.md 的非目标。
- 使用文档必须包含团队部署与公网暴露的说明。
