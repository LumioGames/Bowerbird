# ADR-047：删除文件夹也遵守「被引用」规则，只移入回收站、不删除别的东西

状态：提议
日期：2026-11-25

## 背景

审查发现：删除文件夹时，里面被别的资产引用的资产直接进了回收站，没有返回「被引用」；清理残留时会把被忽略的文件（以点开头的目录、`.bbignore` 里的规则、`*.part` 等）永久删除；也没有拦住 `.bowerbird` 本身。忽略规则的意思是「不管理」，不是「可以删」。

本条是第一期实现时（内核审查之后）按 ADR-013 补的，待评审。

## 决策

- 删除文件夹时，里面有资产被文件夹**外**的资产引用：接口不带 `force` 时返回 `referenced`，并列出引用方；界面在确认框里列出引用方，确认后带 `force`。
- 只把资产（文件 + `.bmeta`）移入回收站。`_folder.bmeta` 随文件夹一起移入回收站；被忽略的文件与未登记的文件原样留下，文件夹因此不空时保留文件夹。
- 拒绝删除库根、`.bowerbird` 及其内部、被忽略的文件夹。
- 同样的「不永久删除」约束适用于移动与上传时的「替换」、重新定位：被替换掉的一律进回收站并写回收信息，未登记的文件不覆盖、改为返回 `conflict`。

## 替代方案与否决理由

- **文件夹删除一律强制**：会在不知情的情况下制造断链。
- **连同被忽略的文件一起移入回收站**：回收站里会出现 Bowerbird 不管理的东西，恢复时语义不清。

## 兼容影响

- knowledge/features/sync-and-integrity.md「删除与回收站」；api-and-agent.md `DELETE /folders` 增加 `force`。
