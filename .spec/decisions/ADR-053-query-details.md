# ADR-053：查询细则——文本语法在执行时解析并按字段与筛选合并、相对时间、分面、附属文件、关键词权重、排序与分页

状态：提议
日期：2026-11-26

## 背景

search.md 规定了查询模型、文本语法与「关键词和语义结果融合」，下面这些没定：
- 同一个请求里既有搜索框文字（`q`）又有结构化条件（`filter`）时，怎么合并；
- 智能文件夹里的「本周」存成什么；
- 分面按什么计数；
- 关键词各字段的权重；
- 少于三个字的词怎么办。

本条把第一期实现时自行定下的做法合并成文（ADR-013），待评审。

## 决策

**`q` 与 `filter`**
- `q` 里的文本语法在执行查询时才解析，相对时间以执行那一刻为准。
- 与 `filter` 按字段合并：
  - `filter` 里给了的字段，覆盖文本里的同一字段，不取交集；
  - 只在文本里出现的字段补进来；
  - `tags` 按 `all`、`any`、`none` 分别合并，`tech` 按键合并，都是 `filter` 优先。
- 相对时间：`when:`（修改时间）与 `created:`（创建时间）的 `today`、`week`、`month`，指最近 24 小时、7 天、30 天，不是日历上的今天、本周、本月。

**智能文件夹**
- 相对时间（`when:`、`created:`）与 `belongs:<名字>` 以文本语法存在 `q` 里，打开时才换算。这样「本周改过的」一直是本周。

**分面**
- 按匹配结果计数：格式、阶段、校验状态，以及前 200 个标签。
- 有搜索词时，只统计融合后的命中列表。这个列表的上限是搜索插件返回的条数，至少 1000。

**附属文件**
- 查询给了 `ids` 时，不默认排除附属文件：按标识取，就是要那几个。

**关键词搜索插件**
- 用 SQLite FTS5 的 trigram 分词。各字段权重：

  | 字段 | 权重 |
  |------|------|
  | 文件名主干 | 10 |
  | 标签 | 10 |
  | 描述、AI 描述、AI 标签、文件夹名、提示词 | 4 |
  | 正文 | 1 |

- 文件名主干与搜索词完全相同加 50，前缀相同加 10。
- 少于三个字的词无法用 trigram 匹配，改为在各字段里找子串，分数为命中字段的权重之和。
- 长短词混合时，长词走全文索引，短词再按子串过滤。
- 正文只取前 20 万字。
- 候选不超过 5000 个时，直接带进 SQL 过滤。
- 没有任何搜索插件时，内核在名字、标签、描述里找子串，权重分别为 3、2、1。

**排序与分页**
- 排序键只收下表这些，`order` 只收 `asc` 与 `desc`。

  | 排序键 | 默认方向 | 说明 |
  |--------|----------|------|
  | `relevance` | 降序 | 只在有搜索词时有效，否则按修改时间 |
  | `name` | 升序 | |
  | `modified` | 降序 | |
  | `created` | 降序 | |
  | `size` | 降序 | |
  | `format` | 升序 | 同格式再按名字 |

- 融合用倒数排名（k = 60）。只有一路结果时，保持插件给的顺序与分数。
- 分页用不透明的游标：
  - 按字段排序用键集，按相关度用偏移；
  - 换了排序的游标拒绝。
- `limit` 默认 50，最多 1000。有搜索词、但按别的字段排序时，最多处理 1 万条命中。

## 替代方案与否决理由

- **`q` 与 `filter` 取交集**：外壳把条件片写进 `q`、Agent 又在 `filter` 里改同一个字段时，取交集常常得到空结果，人看不出为什么。
- **智能文件夹保存时把「本周」换算成日期**：过一周就不再是「本周」了。
- **分面按全库计数**：筛选之后，看不出还剩什么可选。
- **少于三个字的词直接不搜**：中文里两个字的词很常见。
