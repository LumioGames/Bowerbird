# 搜索

搜索只有一个入口，由三层能力叠加：内核自带的结构化筛选、内置插件提供的关键词检索、可选插件提供的语义检索。人在搜索框里用的和 Agent 通过接口用的是同一套查询模型。

## 背景 / 目标

- Agent 要能可靠地限定范围，例如“只要运行时物料里的模型”。
- 人要能用自然的关键词找到资产，包括用当初的提示词找回 AI 生成的资产。
- 语义检索依赖 AI 模型，必须可插拔；没有它时搜索照常可用。
- 十万级资产下，筛选和关键词检索要在交互可接受的时间内返回。

## 设计

### 查询模型

一次查询由下面几部分组成，全部可选：

```jsonc
{
  "q": "红色的卡通宝箱",                 // 查询词，可以夹带文本语法
  "filter": {
    "stage":  ["runtime"],
    "format": ["model", "image"],
    "tags":   { "all": ["道具"], "any": ["宝箱", "箱子"], "none": ["废弃"] },
    "folder": "props/",                  // 含子文件夹
    "review": ["approved"],
    "hasIssues": false,
    "tech":   { "triangles": { "lte": 5000 }, "width": { "gte": 512 } },
    "relation": { "type": "belongs", "to": "<GUID>" },
    "modified": { "after": "2026-11-01T00:00:00Z" },
    "by": "agent",                       // 执行者
    "method": ["ai-generate"],           // 生产方式
    "includeAuxiliary": false,
    "humanTagsOnly": false
  },
  "sort": "relevance",                   // relevance / name / modified / created / size / format
  "order": "desc",                       // asc / desc，不给时取该排序项的默认方向
  "limit": 50,                           // 默认 50，最多 1000
  "cursor": null
}
```

- 没有 `q` 时是纯筛选，按 `sort` 排序，默认按修改时间倒序。
- 有 `q` 时默认按相关度排序。
- 不同筛选字段之间是“且”的关系；同一字段的数组内是“或”的关系。
- 一次查询只查一个资产库，是哪个库由接口路径里的库标识决定。
- **`q` 里的文本语法**在执行查询时解析，相对时间以执行那一刻为准（ADR-053）。解析出的条件与 `filter` 按字段合并：
  - `filter` 里给了的字段覆盖文本里的同一字段，不取交集；
  - 只在文本里的字段补进来；
  - `tags` 按 `all`、`any`、`none` 分别合并，`tech` 按键合并，都是 `filter` 优先；
  - 解析剩下的文字才是查询词。

**排序项**

| 取值 | 含义 |
|------|------|
| `relevance` | 相关度，只在带查询词时可用，否则按修改时间 |
| `name` | 名称，默认升序 |
| `modified` | 修改时间，默认降序 |
| `created` | 创建时间，默认降序 |
| `size` | 大小，默认降序 |
| `format` | 格式，默认升序；同格式再按名称 |

只收这几个排序项，`order` 只收 `asc` 与 `desc`。

### 筛选字段

| 字段 | 取值 | 说明 |
|------|------|------|
| `stage` | 物料阶段的数组 | |
| `format` | 格式标识的数组 | 取值来自已启用的格式插件，加上 `unknown` |
| `tags.all` / `tags.any` / `tags.none` | 标签数组 | 全部包含、任一包含、都不包含 |
| `folder` | 资产库内的相对路径 | 含子文件夹；加 `folderExact: true` 只匹配该层 |
| `review` | 有效校验状态的数组 | |
| `hasIssues` | 布尔 | 是否带有错误级或警告级的完整性问题 |
| `issue` | 问题类型的数组 | 限定具体问题类型 |
| `tech.<键>` | 比较条件：`eq`、`gte`、`lte`、`gt`、`lt` | 键由格式插件定义，例如 `width`、`duration`、`triangles` |
| `relation` | 关系类型与对方 GUID，可加方向 | 例如归属于某个设计对象的全部资产 |
| `created` / `modified` | `after`、`before` | |
| `by` | 执行者 | 资产的创建者。可以只写类别：`agent` 匹配所有 Agent，`agent:modeler` 只匹配这一个 |
| `method` | 生产方式的数组 | 产出该资产的生产记录的方式，例如 `ai-generate`；插件自定义的值带插件标识前缀 |
| `includeAuxiliary` | 布尔，默认 `false` | 是否包含附属文件 |
| `humanTagsOnly` | 布尔，默认 `false` | 标签条件是否只匹配人工标签 |
| `inTrash` | 布尔，默认 `false` | |
| `ids` | GUID 数组 | 只在这些资产里查；给了时不默认排除附属文件（ADR-053） |
| `untagged` | 布尔 | 人工标签与 AI 标签都没有，即「未打标签」视图 |
| `similarTo` | GUID 或图片 | 以图搜图，见下文「语义检索」 |

### 文本语法

搜索框和命令行支持把筛选条件写在查询词里，由内核解析成上面的结构：

```text
stage:runtime format:model tag:宝箱 -tag:废弃 tris:<5000 folder:props/ 宝箱
```

值里有空格时用双引号括起来，例如 `tag:"two words"`。

| 写法 | 含义 |
|------|------|
| `stage:<值>` | 物料阶段 |
| `format:<值>` | 格式 |
| `tag:<值>` / `-tag:<值>` | 包含 / 不包含标签 |
| `folder:<路径>` | 文件夹 |
| `review:<值>` | 校验状态 |
| `is:issue` / `is:stale` / `is:missing` | 带问题 / 上游已更新 / 文件缺失 |
| `<技术信息键>:<比较符><数值>` | 技术信息条件，如 `width:>=1024`、`duration:<5`；比较符为 `<`、`<=`、`>`、`>=`、`=`，不写时为等于 |
| `tris:<比较符><数值>` / `dur:<比较符><数值>` | `triangles`（三角面数）与 `duration`（时长）的简写 |
| `belongs:<GUID 或名称>` | 归属于某个设计对象 |
| `when:today` / `when:week` / `when:month` | 修改时间在最近 24 小时、7 天、30 天之内 |
| `created:today` / `created:week` / `created:month` | 创建时间在最近 24 小时、7 天、30 天之内（ADR-034） |
| `by:<执行者>` | 按执行者筛选，如 `by:agent`、`by:agent:modeler` |
| `method:<值>` | 按生产方式筛选，如 `method:ai-generate` |
| 其余文字 | 作为查询词 |

`when:` 与 `created:` 解析成 `modified` 与 `created` 的时间范围；`tris:` 与 `dur:` 解析成对应的技术信息条件。不认识的写法留在查询词里。

界面上的筛选面板与文本语法双向同步：在面板里勾选的条件会体现在搜索框里，反之亦然。

### 检索与融合

处理一次查询的步骤：

1. **筛选**：内核按 `filter` 在索引里得到候选集合。
2. **检索**：有查询词时，把查询词和候选集合交给每个已启用的搜索插件，各自返回带分数的命中列表；候选不超过 5000 个时直接交给插件过滤。没有任何搜索插件时，内核在名字、标签、描述里找子串。
3. **融合**：用倒数排名融合（k = 60）把多路结果合并成一个排序，再按筛选条件过滤一遍。只有一路结果时保持插件的顺序与分数。
4. **分页**：按 `limit` 与 `cursor` 返回。游标不透明：按字段排序用键集，按相关度用偏移；换了排序的游标拒绝。有查询词、但按别的字段排序时，最多处理 1 万条命中。

融合不依赖各插件分数的量纲，只用各自的排名，所以增加新的搜索插件不需要调参。

### 关键词检索

由内置插件 `bowerbird.search-keyword` 提供，基于 SQLite 的全文检索。

**检索范围**

| 内容 | 权重 |
|------|------|
| 文件名（不含后缀） | 10；与查询词完全相同再加 50，前缀相同再加 10 |
| 人工标签 | 10 |
| 描述 | 4 |
| AI 标签与 AI 描述 | 4 |
| 路径中的文件夹名 | 4 |
| 生产记录里的提示词 | 4 |
| 文档正文、格式插件提取的文本 | 1；只取前 20 万字 |

- **中文处理**：用 SQLite FTS5 的 trigram 分词，按字符三元组切分建立索引，可以做任意子串匹配，不依赖分词词典。
- 少于三个字的查询词退化为逐字段的子串匹配，分数为命中字段的权重之和；长短词混合时，长词走全文索引，短词再按子串过滤。
- 索引放在插件自己的数据目录里（ADR-028）。
- 命中名字以外的字段时，结果带一段约 64 字的片段与高亮位置。

### 语义检索

由可选插件提供，第一期之后实现。接口约定：

- 插件自带或配置一个向量模型，可以是本机模型，也可以是外部服务。
- 文本向量取自名称、标签、描述、提示词的组合。
- 图像向量取自缩略图，使模型、视频也能参与“以文搜图”和“以图搜图”。模型与视频的缩略图要等有人打开页面后才渲染，在那之前它们没有图像向量。
- 向量由插件保存在自己的数据库里，绑定模型标识；更换模型后需要重建。
- 以图搜图通过筛选里的 `similarTo` 字段表达，值为一个资产的 GUID 或一张上传的图片。入口由语义插件通过界面扩展点提供，外壳不画（ADR-039）。

现在带 `similarTo` 的查询一律返回“不支持”，其余查询不受影响；搜索插件的接口还没有接收它的途径。

### 结果

搜索返回精简的资产摘要，字段固定：

| 字段 | 说明 |
|------|------|
| `id` | GUID |
| `name` | 文件名 |
| `path` | 资产库内的相对路径；停放的缺失资产给原路径 |
| `format` | 格式标识 |
| `plugin` | 认领它的插件 |
| `stage` | 物料阶段 |
| `review` | 有效校验状态 |
| `tags` | 人工标签 |
| `autoTags` | AI 标签 |
| `description` | 描述的第一句，人工描述优先 |
| `flags` | 标记：`stale`、`broken`、`missing`、`processing`、`failed` |
| `thumbnail` | 缩略图地址，地址里带缓存键，可以长期缓存 |
| `thumbState` | 缩略图的状态：`ready` 已有、`pending` 处理中、`render` 等浏览器渲染、`none` 不生成、`failed` 失败 |
| `aspect` | 缩略图的宽高比（宽除以高），供瀑布流在缩略图加载之前排版；还没有缩略图时为空 |
| `badge` | 角标文本，由格式插件给出，例如「2,480 面」「0:03」「1024×1024」 |
| `issueLevel`、`issueCount` | 最高的问题级别与问题数 |
| `size`、`created`、`modified`、`createdBy` | 大小、创建与修改时间、创建者 |
| `bundle`、`auxiliary` | 是否包式资产、是否附属文件 |
| `memberCount` | 归属于它的资产数，大于 0 的是设计对象 |
| `cellText` | 没有图片缩略图的格式（文档）在网格里显示的标题与摘录 |
| `missingPlugin` | 读这个文件需要、但本机没有的插件 |
| `score`、`hit` | 相关度与命中片段，仅带查询词时返回 |

- 响应还包含总数的估计值、下一页的游标，以及在请求时可选返回的分面统计：按格式、阶段、校验状态、标签（前 200 个）的数量。
- 分面按匹配结果计数（ADR-053）。有查询词时，总数与分面只统计融合后的命中列表，上限是搜索插件返回的条数，至少 1000。
- Agent 的查询被 `agentSearchScope` 收窄时，响应带 `scopedToApproved`。

### 默认范围

- 默认不包含附属文件和回收站里的资产。
- 默认包含所有校验状态的资产，每条结果都带 `review` 字段。
- 资产库设置 `agentSearchScope` 为 `approved` 时，来自 Agent 的查询在未显式指定 `review` 条件的情况下只返回已通过和免审的资产。

### 智能文件夹

智能文件夹是保存下来的一次查询，存为 `.bowerbird/views/` 下的一个文件，内容就是查询模型加一个显示名称。它出现在界面左栏，点开即执行该查询。例如「AI 生成待审」是 `review` 为 `pending` 加 `method` 为 `ai-generate`。

相对时间（`when:`、`created:`）与 `belongs:<名称>` 以文本语法存在 `q` 里，打开时才换算，「本周改过的」一直是本周（ADR-053）。

内核预置几个不可删除的视图：全部、未打标签、待审、有问题、回收站。

### 性能目标

以十万个资产的库、普通笔记本电脑为基准，由 `tests/perf/run-perf.mjs` 测量：

| 操作 | 目标 |
|------|------|
| 纯筛选查询 | 100 毫秒内 |
| 关键词查询 | 200 毫秒内 |
| 首屏结果渲染 | 500 毫秒内 |

## 待解决

- 标签别名（如“宝箱”与“chest”）是否在查询时自动展开，待定；目前别名只用于标签管理。
- 语义检索中文本向量与图像向量是否使用同一个多模态模型，留给语义插件设计时决定。
