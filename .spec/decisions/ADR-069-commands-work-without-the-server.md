# ADR-069：服务没开时，命令自己打开资产库读写

状态：Accepted
日期：2026-11-27

## 背景

- 现在除了初始化与插件管理，所有命令都要先有一个 `bb serve` 在运行，命令只是把请求转给它。
- 资产库文件夹是唯一真值（ADR-002）。记下一条信息，本质上是往磁盘写一个文件，这件事并不需要常驻的服务。服务真正的用处是三样：给人看的网页、盯着文件夹的变化、生成缩略图。
- 一次真实项目接入的使用反馈（2026-11-27）：宿主应用中途把服务停掉，之后的命令全部失败；Agent 每次都要先查端口、起服务、用完再关，等于额外照看一个进程。

## 决策

- 服务是用来看和加速的，不是读写资产库的前提。
- 命令执行时：
  - 服务开着：照旧把请求交给服务。
  - 服务没开：命令自己打开资产库，读或写完就退出。
- 服务没开时，命令开头先对一遍账，因为这段时间没人盯着文件夹。
- 缩略图、概览图这类加工不在命令里做，留到下次服务启动。
- 同一个资产库同一时刻只有一个进程在写，用一把锁保证。

## 替代方案与否决理由

- **发现没有服务时自动在后台起一个**（反馈的建议）：进程还在，只是换成由 Bowerbird 替 Agent 照看。它照样会被宿主关掉，还会留下没人管的后台进程。
- **保持现状，在说明里写清楚要先开服务**：没有解决问题，只是告知。

## 兼容影响

- 改口 [ADR-002](ADR-002-local-first-monolith.md) 的「一个服务进程」：读写资产库的可以是服务，也可以是一条命令；同一时刻只有一个在写。其余各条不变。
- 改口 [ADR-050](ADR-050-distribution-and-cli.md)：命令不再一律连接 `BOWERBIRD_URL`，连不上时改为自己打开资产库。
- knowledge/features/api-and-agent.md：命令行一节、给 Agent 的接入步骤。
- knowledge/features/engineering.md：进程模型、锁。
- knowledge/features/sync-and-integrity.md：扫描的触发方式增加「命令开头」。
- README.md 与 docs/usage.md：接入步骤里「启动服务（常驻）」不再是必须的一步。
- 为什么安全：另一台电脑通过云盘改同一个文件夹的情况，已经由对账规则与写入前的核对（ADR-046）处理；另一个进程来写是同一种情况。
- 代价：大资产库上，服务没开时每条命令要多等一次对账。估计十万资产的库是几秒，这个数没有实测；这种库建议开着服务用。

## 实现时要定的

- 锁放在哪、服务与命令怎么互相发现。
- 命令怎么知道要打开哪个资产库（现在由服务的默认资产库决定）。
- MCP 服务是否也照此处理。
- 十万资产的库上，命令开头对账的实际耗时，量过之后写进性能基准。
